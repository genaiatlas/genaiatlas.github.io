    Introduction & Context

    This tutorial demonstrates building five different types of recommendation systems using Yelp restaurant data. The case study covers both traditional collaborative filtering approaches and modern matrix factorization techniques, providing a comprehensive foundation for understanding recommendation system methodologies.

    Business Context:

    Yelp connects users with local businesses through crowd-sourced reviews and ratings. The platform processes massive amounts of user-business interaction data across multiple cities and countries, making it an ideal case study for recommendation systems that can help users discover new restaurants they're likely to enjoy.

    Tutorial Objectives:

    • Knowledge/Rank-Based Systems: Build popularity-based recommendations for cold start scenarios

    • Similarity-Based Filtering: Implement both user-user and item-item collaborative filtering

    • Matrix Factorization: Apply SVD for latent feature discovery

    • Clustering Approaches: Use co-clustering for segmented recommendations

    • Performance Assessment: Evaluate systems using precision@k, recall@k, and F1-score metrics

    Methodological Foundation:

    Each approach addresses different recommendation challenges. Rank-based systems handle new users with no history, collaborative filtering leverages user behavior patterns, matrix factorization discovers hidden preference structures, and clustering captures user segments with similar tastes.

    Dataset Overview & Exploration

    Data Structure:

    The Yelp dataset contains user reviews, business metadata, and interaction patterns across 10 cities in 4 countries. For computational efficiency, this tutorial uses a subset focusing on four key attributes:

    • business_id: Unique restaurant identifier

    • user_id: Unique user identifier

    • stars: Rating scale (1-5)

    • business_name: Restaurant name (dropped for modeling)

    Key Dataset Characteristics:

    • Scale: 229,907 total interactions between 45,981 unique users and 11,537 unique restaurants

    • Sparsity: Only 0.04% of possible user-restaurant combinations have ratings, creating a classic sparse matrix problem

    • Rating Distribution: Heavily skewed toward ratings 4 and 5, indicating users tend to rate restaurants they enjoy rather than those they dislike

    Data Filtering Strategy:

    The tutorial implements a practical filtering approach, retaining only users with at least 100 ratings. This decision balances computational efficiency with recommendation quality by ensuring sufficient user behavior data for meaningful pattern detection.

    Critical Insights:

    • Most Active Restaurant: One restaurant received 844 ratings, yet 45,137 users haven't interacted with it, representing significant recommendation opportunity

    • Power Users: The most active user rated 588 restaurants, leaving 10,949 unrated restaurants for potential recommendations

    • Business Implications: The sparsity pattern reveals why recommendation systems are essential for platforms like Yelp

    Limitations:

    • Filtering reduces dataset size, potentially excluding valuable long-tail preferences

    • Rating bias toward positive experiences may skew recommendation quality

    • Geographic and temporal factors aren't considered in this simplified analysis

    Model 1: Rank-Based Recommendation

    Methodology:

    Rank-based systems provide recommendations using aggregate popularity metrics, making them ideal for cold start scenarios where user history is unavailable. This approach calculates average ratings per restaurant and ranks them by popularity.

    Implementation Logic:

    The system computes two key metrics:

    • Average Rating: Mean star rating across all user reviews

    • Rating Count: Total number of user interactions

    Restaurants are ranked by average rating, with a minimum interaction threshold to ensure statistical reliability.

    Practical Applications:

    • New User Onboarding: Immediately provide recommendations without requiring user preference data

    • Geographic Expansion: Recommend popular venues in new cities

    • Baseline Performance: Establish minimum recommendation quality expectations

    Performance Characteristics:

    Rank-based systems excel in simplicity and interpretability but lack personalization. They perform well for mainstream preferences but poorly for niche tastes or discovering hidden gems.

    Business Value:

    • Immediate Deployment: No training period required

    • Universal Coverage: Works for any user regardless of history

    • Marketing Alignment: Naturally promotes high-performing businesses

    Key Limitations:

    • No Personalization: Same recommendations for all users

    • Popularity Bias: Reinforces existing popular choices, potentially missing niche preferences

    • Static Recommendations: Doesn't adapt to user feedback without manual recomputation

    When to Use:

    Most effective as a fallback strategy for new users or as a baseline for measuring other recommendation approaches. Consider combining with personalized methods for hybrid systems.

    Model 2: User-User Collaborative Filtering

    Methodology:

    User-user collaborative filtering identifies users with similar rating patterns and recommends restaurants liked by similar users. This approach assumes users with similar past preferences will enjoy similar future experiences.

    Core Algorithm:

    The system uses K-Nearest Neighbors (KNN) with cosine similarity to find users with comparable rating patterns. For each target user, the algorithm:

    • Calculates similarity scores with all other users

    • Identifies the k most similar users (neighbors)

    • Predicts ratings based on neighbor preferences

    Similarity Calculation:

    Cosine similarity measures the angle between user rating vectors, effectively capturing preference alignment regardless of rating scale differences between users.

    Performance Results:

    • Baseline Model: F1-score of 0.542, indicating moderate recommendation quality

    • Optimized Model: Hyperparameter tuning with GridSearchCV maintained similar performance

    • RMSE: Measures prediction accuracy for numerical ratings

    Hyperparameter Optimization:

    Key parameters tuned include:

    • k (neighbors): Number of similar users to consider

    • min_k: Minimum neighbors required for prediction

    • similarity_metric: Cosine vs. Mean Squared Difference

    Practical Insights:

    • Precision (77.3%): Most recommended restaurants are relevant to users

    • Recall (42%): System captures less than half of truly relevant restaurants

    • Trade-offs: High precision but moderate recall suggests conservative recommendations

    Strengths:

    • Intuitive Logic: Recommendations based on "people like you" principle

    • Adaptability: Naturally incorporates new user feedback

    • Transparency: Can explain recommendations through similar user identification

    Limitations:

    • Scalability Issues: Computation grows quadratically with user count

    • Sparsity Problems: Similarity calculation difficult with limited overlap

    • Cold Start: Cannot recommend for users without sufficient rating history

    Business Applications:

    Most effective for platforms with dense user-item interactions and stable user bases. Works well for discovering restaurants within established preference patterns but may miss innovative or emerging trends.

    Model 3: Item-Item Collaborative Filtering

    Methodology:

    Item-item collaborative filtering identifies restaurants with similar rating patterns across users and recommends items liked by users who enjoyed similar restaurants. This approach often proves more stable than user-based filtering due to item relationships changing less frequently than user preferences.

    Algorithmic Approach:

    The system calculates restaurant similarity using the same KNN framework but focuses on item relationships rather than user similarities. For each restaurant, the algorithm identifies similar establishments based on user rating patterns.

    Key Differences from User-User Filtering:

    • Stability: Restaurant similarities remain more consistent over time

    • Interpretability: "People who liked X also liked Y" explanations

    • Scalability: Often fewer items than users in most domains

    Performance Results:

    • Baseline F1-score: 0.450, slightly lower than user-user filtering

    • Optimized Performance: Significant improvement through hyperparameter tuning

    • Best Configuration: MSD similarity metric with k=30, min_k=9

    Optimization Outcomes:

    The tuned model showed substantial improvement over baseline, demonstrating the importance of proper hyperparameter selection for item-based approaches.

    Practical Advantages:

    • Stable Recommendations: Item relationships change less frequently than user preferences

    • Better Explanations: Natural to explain why restaurants are recommended

    • Efficient Updates: Pre-computed item similarities reduce real-time computation

    Business Value:

    • Menu Engineering: Understanding restaurant similarity helps with competitive analysis

    • Marketing Campaigns: Target users of similar restaurants

    • Inventory Management: Predict demand patterns based on similar establishment performance

    Limitations:

    • Limited Diversity: May create filter bubbles by recommending very similar restaurants

    • Popularity Bias: Tends to recommend popular items with more interaction data

    • Cold Start for Items: New restaurants lack similarity data

    Performance Considerations:

    Item-item filtering performed well in this case study, particularly after optimization. The approach balance interpretability with recommendation quality, making it suitable for business applications requiring explainable recommendations.

    Model 4: Matrix Factorization (SVD)

    Methodology:

    Singular Value Decomposition (SVD) represents the most sophisticated approach in this tutorial, discovering latent factors that explain user preferences and restaurant characteristics. This matrix factorization technique decomposes the user-item rating matrix into lower-dimensional representations.

    Mathematical Foundation:

    SVD approximates ratings using the formula: 

    r̂ui = μ + bu + bi + qiᵀpu

    Variable Definitions:

    • μ = global average rating

    • bu = user bias term

    • bi = item bias term

    • qi = item factors (restaurant characteristics)

    • pu = user factors (user preferences)

    Learning Process:

    The algorithm minimizes regularized squared error using stochastic gradient descent, iteratively updating user and item factors to better predict known ratings.

    Performance Results:

    • Baseline F1-score: 0.51, competitive with collaborative filtering approaches

    • Optimized Model: Improved performance through hyperparameter tuning

    • Key Parameters: 20 epochs, learning rate 0.01, regularization 0.2

    Hyperparameter Impact:

    • n_epochs: Controls training iterations, balancing accuracy and overfitting

    • lr_all: Learning rate affects convergence speed and stability

    • reg_all: Regularization prevents overfitting to training data

    Practical Advantages:

    • Latent Factor Discovery: Identifies hidden preference patterns not apparent in explicit ratings

    • Scalability: Efficient computation for large datasets once factors are learned

    • Cold Start Handling: Can make predictions for users/items with limited data

    • Dimensionality Reduction: Captures essential patterns in compressed representation

    Business Insights:

    Matrix factorization reveals underlying preference structures that aren't obvious from raw ratings. For restaurants, latent factors might represent cuisine types, price points, ambiance preferences, or service quality dimensions.

    Model Interpretation:

    While less interpretable than similarity-based methods, SVD provides more accurate predictions by capturing complex, non-linear preference patterns that similarity metrics might miss.

    Limitations:

    • Black Box Nature: Difficult to explain specific recommendations to users

    • Parameter Sensitivity: Requires careful tuning for optimal performance

    • Training Complexity: More complex than similarity-based approaches

    • Computational Requirements: Initial training can be resource-intensive

    When to Use:

    SVD works best for applications prioritizing prediction accuracy over interpretability, particularly with large datasets where latent patterns provide significant value over simple similarity measures.

    Model 5: Clustering-Based Recommendation

    Methodology:

    Co-clustering simultaneously groups users and restaurants into clusters, identifying user segments with shared preferences for specific restaurant categories. This approach differs from traditional clustering by clustering both dimensions simultaneously rather than sequentially.

    Co-Clustering Concept:

    The algorithm creates bidirectional clusters where:

    • User Clusters: Groups of users with similar rating patterns

    • Item Clusters: Groups of restaurants with similar user appeal

    • Simultaneous Optimization: Both clusterings optimize together for maximum coherence

    Implementation Details:

    The CoClustering algorithm partitions the user-restaurant matrix into coherent blocks where users within a cluster show similar preferences for restaurants within corresponding item clusters.

    Performance Results:

    • Baseline F1-score: 0.528, competitive with other approaches

    • Optimization Impact: Hyperparameter tuning yielded minimal improvement

    • Stability: Performance remained consistent across different configurations

    Hyperparameter Analysis:

    Key parameters include:

    • n_cltr_u: Number of user clusters (tested 3-6)

    • n_cltr_i: Number of item clusters (tested 3-6)

    • n_epochs: Optimization iterations (tested 30-50)

    Practical Applications:

    • Market Segmentation: Identify distinct user groups with specific restaurant preferences

    • Targeted Marketing: Develop campaigns for user clusters with shared characteristics

    • Restaurant Positioning: Understand competitive clusters and positioning opportunities

    Business Value:

    • Strategic Insights: Reveals market structure and user segmentation patterns

    • Scalable Recommendations: Pre-computed clusters enable efficient recommendation generation

    • Interpretable Segments: Clusters provide actionable business intelligence

    Clustering Interpretation:

    User clusters might represent demographics (families, young professionals, food enthusiasts) while restaurant clusters could indicate categories (fast food, fine dining, ethnic cuisine).

    Limitations:

    • Fixed Segmentation: Users and restaurants locked into specific clusters

    • Limited Personalization: Recommendations based on cluster membership rather than individual preferences

    • Cluster Quality: Performance depends heavily on meaningful cluster formation

    • Parameter Sensitivity: Choosing optimal cluster numbers requires domain knowledge

    Comparison with Other Methods:

    Co-clustering provides unique insights into market structure but doesn't necessarily outperform other methods in recommendation accuracy. Its primary value lies in interpretability and business intelligence rather than pure prediction performance.

    Performance Evaluation & Comparison

    Evaluation Framework:

    The tutorial employs precision@k, recall@k, and F1-score@k metrics to assess recommendation quality, providing a comprehensive view of system performance beyond simple accuracy measures.

    Metric Definitions:

    • Precision@k: Fraction of top-k recommendations that are relevant (rating ≥ 3.5)

    • Recall@k: Fraction of relevant items captured in top-k recommendations

    • F1-score@k: Harmonic mean balancing precision and recall

    Performance Summary:

    Model F1-Score Precision Recall Key Strength
    User-User CF 0.542 77.3% 42% Intuitive explanations
    Item-Item CF ~0.450 - - Stable relationships
    Matrix Factorization 0.51 - - Latent pattern discovery
    Co-Clustering 0.528 - - Market segmentation

    Critical Performance Analysis:

    Strengths:

    • All models achieve reasonable F1-scores (45-54%), indicating practical utility

    • High precision across models suggests recommendations are generally relevant

    • Different models excel in different scenarios and use cases

    Limitations:

    • Moderate recall values indicate systems miss many relevant restaurants

    • Performance differences are relatively small, suggesting similar underlying data constraints

    • No single model dominates across all metrics

    Business Implications:

    • Conservative Recommendations: High precision/moderate recall suggests systems err on the side of safety

    • Opportunity Cost: Low recall indicates significant untapped recommendation potential

    • Model Selection: Choose based on specific business requirements rather than pure performance

    Evaluation Considerations:

    • Threshold Sensitivity: 3.5 rating threshold may not reflect true user preferences

    • k-Value Impact: Evaluation limited to top-10 recommendations

    • Dataset Bias: Filtered dataset may not represent full user diversity

    Honest Assessment:

    While all models show promise, none achieve exceptional performance levels. The moderate F1-scores reflect inherent challenges in recommendation systems including data sparsity, rating bias, and the complexity of human preferences.

    Practical Recommendations:

    • Hybrid Approaches: Combine multiple models to leverage respective strengths

    • Dynamic Weighting: Adjust model weights based on user context and item characteristics

    • Continuous Learning: Implement feedback loops to improve recommendations over time

    Top-N Recommendation Function

    def top_n_restaurant(data, n, min_interaction=100):
    """
    Generate top-n restaurant recommendations based on average ratings.

    Parameters:
    data (DataFrame): Rating data with 'avg_rating' and 'rating_count' columns
    n (int): Number of recommendations to return
    min_interaction (int): Minimum number of interactions required

    Returns:
    Index: Business IDs of top-n recommended restaurants
    """
    # Filter restaurants with minimum interactions
    recommendations = data[data['rating_count'] > min_interaction]

    # Sort by average rating (descending)
    recommendations = recommendations.sort_values(by='avg_rating', ascending=False)

    return recommendations.index[:n]

# Example usage
top_5_restaurants = list(top_n_restaurant(final_rating, 5, 50))
print("Top 5 restaurants with minimum 50 interactions:")
print(top_5_restaurants)

    Purpose: Implement flexible rank-based recommendation system with configurable parameters for different use cases.

    Flow: Filter by minimum interactions → Sort by average rating → Return top-n results

    Impact: Provides baseline recommendations for cold start scenarios. Parameter flexibility enables different business requirements.

    Mathematical Foundation:

    Rank-based systems use simple aggregation: 

    Restaurant_Score = (Σ ratings) / (number_of_ratings)

    The minimum interaction threshold ensures statistical reliability by requiring sufficient sample size for meaningful averages.

    Baseline SVD Model

    Purpose: Implement baseline Singular Value Decomposition for matrix factorization-based collaborative filtering.

    Flow: Initialize SVD with default parameters → Train on training set

    Impact: Creates foundation for latent factor-based recommendations, capturing hidden patterns in user-item interactions.

    Mathematical Foundation:

    SVD decomposes the user-item rating matrix R into three matrices: 

    R ≈ U × Σ × V^T

    The prediction formula in Surprise's SVD: 

    r̂_ui = μ + b_u + b_i + q_i^T × p_u

    Where:

    • μ = global mean rating

    • b_u = user bias

    • b_i = item bias

    • q_i = item factor vector

    • p_u = user factor vector

    SVD Training Process

    The SVD algorithm uses stochastic gradient descent to minimize the regularized squared error:

    min Σ(r_ui - r̂_ui)² + λ(||p_u||² + ||q_i||² + b_u² + b_i²)

    Update rules: 

    b_u ← b_u + γ(e_ui - λb_u)
b_i ← b_i + γ(e_ui - λb_i)
p_u ← p_u + γ(e_ui × q_i - λp_u)
q_i ← q_i + γ(e_ui × p_u - λq_i)

    Where e_ui = r_ui - r̂_ui is the prediction error.

    Performance Evaluation Functions

    Precision and Recall at K Function

    def precision_recall_at_k(model, k=10, threshold=3.5):
    """
    Calculate precision@k and recall@k for recommendation model.

    Parameters:
    model: Trained recommendation model
    k (int): Number of top recommendations to consider
    threshold (float): Rating threshold for relevance (default 3.5)

    Returns:
    Prints precision, recall, and F1-score metrics
    """
    # Dictionary to store predictions per user
    user_est_true = defaultdict(list)

    # Generate predictions on test set
    predictions = model.test(testset)

    # Group predictions by user
    for uid, _, true_r, est, _ in predictions:
        user_est_true[uid].append((est, true_r))

    # Calculate metrics for each user
    precisions = dict()
    recalls = dict()

    for uid, user_ratings in user_est_true.items():
        # Sort by estimated rating (descending)
        user_ratings.sort(key=lambda x: x[0], reverse=True)

        # Count relevant items (actual rating >= threshold)
        n_rel = sum((true_r >= threshold) for (_, true_r) in user_ratings)

        # Count recommended items in top k (estimated rating >= threshold)
        n_rec_k = sum((est >= threshold) for (est, _) in user_ratings[:k])

        # Count relevant AND recommended items in top k
        n_rel_and_rec_k = sum(((true_r >= threshold) and (est >= threshold))
                              for (est, true_r) in user_ratings[:k])

        # Calculate precision@k (avoid division by zero)
        precisions[uid] = n_rel_and_rec_k / n_rec_k if n_rec_k != 0 else 0

        # Calculate recall@k (avoid division by zero)
        recalls[uid] = n_rel_and_rec_k / n_rel if n_rel != 0 else 0

    # Calculate overall metrics
    precision = round(sum(prec for prec in precisions.values()) / len(precisions), 3)
    recall = round(sum(rec for rec in recalls.values()) / len(recalls), 3)
    f1_score = round((2 * precision * recall) / (precision + recall), 3) if (precision + recall) > 0 else 0

    # Calculate and display RMSE
    accuracy.rmse(predictions)

    # Display results
    print(f'Precision@{k}: {precision}')
    print(f'Recall@{k}: {recall}')
    print(f'F1-score@{k}: {f1_score}')

    return precision, recall, f1_score

    Purpose: Comprehensive evaluation function that calculates key recommendation system metrics with proper edge case handling.

    Flow: Group predictions by user → Sort by estimated rating → Count relevant/recommended items → Calculate metrics → Display results

    Impact: Provides standardized evaluation across all models, enabling fair comparison and performance assessment.

    Mathematical Definitions:

    • Precision@k: P@k = |{relevant items} ∩ {recommended items}| / |{recommended items}|

    • Recall@k: R@k = |{relevant items} ∩ {recommended items}| / |{relevant items}|

    • F1-score@k: F1@k = 2 × (P@k × R@k) / (P@k + R@k)

    Recommendation Generation Function

    def get_recommendations(data, user_id, top_n, algo):
    """
    Generate top-n recommendations for a specific user.

    Parameters:
    data (DataFrame): User-item interaction data
    user_id (str): Target user ID
    top_n (int): Number of recommendations to generate
    algo: Trained recommendation algorithm

    Returns:
    list: Top-n recommendations as (item_id, predicted_rating) tuples
    """
    # Create user-item interaction matrix
    user_item_interactions_matrix = data.pivot_table(
        index='user_id', 
        columns='business_id', 
        values='stars'
    )

    # Find items not yet interacted with by the user
    non_interacted_products = user_item_interactions_matrix.loc[user_id][
        user_item_interactions_matrix.loc[user_id].isnull()
    ].index.tolist()

    # Generate predictions for non-interacted items
    recommendations = []
    for item_id in non_interacted_products:
        # Predict rating for this user-item pair
        est = algo.predict(user_id, item_id).est
        recommendations.append((item_id, est))

    # Sort by predicted rating (descending) and return top-n
    recommendations.sort(key=lambda x: x[1], reverse=True)
    return recommendations[:top_n]

    Purpose: Generate personalized recommendations by predicting ratings for unrated items and selecting top candidates.

    Flow: Create interaction matrix → Identify unrated items → Generate predictions → Sort and select top-n

    Impact: Core function for practical recommendation generation, enabling personalized suggestions for any user.

    Recommendation Ranking Function

    def ranking_products(recommendations, final_rating):
    """
    Rank recommended products using corrected ratings that account for rating count.

    Parameters:
    recommendations (list): List of (business_id, predicted_rating) tuples
    final_rating (DataFrame): Business ratings with avg_rating and rating_count

    Returns:
    DataFrame: Ranked recommendations with corrected ratings
    """
    # Extract business IDs from recommendations
    business_ids = [items[0] for items in recommendations]

    # Get rating information for recommended businesses
    ranked_products = final_rating.loc[business_ids].sort_values(
        'rating_count', ascending=False
    )[['rating_count']].reset_index()

    # Merge with predicted ratings
    ranked_products = ranked_products.merge(
        pd.DataFrame(recommendations, columns=['business_id', 'predicted_ratings']),
        on='business_id',
        how='inner'
    )

    # Calculate corrected ratings (penalize businesses with few ratings)
    ranked_products['corrected_ratings'] = (
        ranked_products['predicted_ratings'] - 1 / np.sqrt(ranked_products['rating_count'])
    )

    # Sort by corrected ratings
    ranked_products = ranked_products.sort_values('corrected_ratings', ascending=False)

    return ranked_products

    Purpose: Improve recommendation quality by adjusting predicted ratings based on rating count reliability.

    Flow: Extract business IDs → Get rating statistics → Merge with predictions → Calculate corrections → Sort results

    Impact: Balances prediction confidence with rating reliability, reducing bias toward businesses with few ratings.

    Mathematical Foundation:

    Corrected rating formula: 

    corrected_rating = predicted_rating - 1/√(rating_count)

    This penalty term reduces confidence in predictions for businesses with fewer ratings, implementing a form of confidence interval adjustment.

    def compare_models(models_dict, data, user_id, top_n=5):
    """
    Compare recommendations from multiple models for a specific user.

    Parameters:
    models_dict (dict): Dictionary of model_name: model pairs
    data (DataFrame): User-item interaction data
    user_id (str): Target user ID
    top_n (int): Number of recommendations per model

    Returns:
    dict: Recommendations from each model
    """
    comparison_results = {}

    for model_name, model in models_dict.items():
        try:
            recommendations = get_recommendations(data, user_id, top_n, model)
            comparison_results[model_name] = recommendations
            print(f"\n{model_name} Recommendations:")
            for i, (business_id, rating) in enumerate(recommendations, 1):
                print(f"{i}. Business ID: {business_id}, Predicted Rating: {rating:.3f}")
        except Exception as e:
            print(f"Error with {model_name}: {str(e)}")
            comparison_results[model_name] = []

    return comparison_results

    Purpose: Enable side-by-side comparison of different recommendation algorithms for the same user.

    Flow: Iterate through models → Generate recommendations → Display results → Handle errors gracefully

    Impact: Facilitates model selection and ensemble method development by comparing algorithm outputs directly.
