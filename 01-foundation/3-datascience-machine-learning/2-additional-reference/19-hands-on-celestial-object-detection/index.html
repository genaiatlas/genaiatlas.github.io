    Problem Context & Astronomical Background

    Scientific Foundation

    This tutorial demonstrates machine learning applications in astronomy through multi-class classification of celestial objects. The objective is to distinguish between Stars, Galaxies, and Quasars using spectroscopic and photometric measurements from the Sloan Digital Sky Survey (SDSS).

    Astronomical Context:

    Stars represent luminous plasma spheroids powered by nuclear fusion, with the Sun being our nearest example. The next closest star, Proxima Centauri, lies approximately 4.25 light-years away, illustrating the vast scales involved in astronomical observations.

    Galaxies are gravitationally bound systems containing 10^8 to 10^14 stars, along with stellar remnants, interstellar gas, cosmic dust, and dark matter. These structures represent some of the largest organized matter formations in the observable universe.

    Quasars (Quasi-stellar objects) are extremely luminous active galactic nuclei powered by supermassive black holes. Their defining characteristic is extreme redshift due to their tremendous distances from Earth, making them observable primarily in the early universe.

    The Redshift Phenomenon

    Critical Insight: Redshift serves as the primary distinguishing feature for quasar identification. This phenomenon occurs because:

    1. Cosmological expansion causes electromagnetic radiation to lose energy over vast distances

    2. Doppler effect creates frequency shifts for objects receding at high velocities

    3. Distance-velocity relationship means more distant objects exhibit higher redshift values

    This physical principle becomes the foundation for our machine learning approach, as algorithms can detect patterns in redshift measurements that correlate with object classifications.

    Problem Formulation

    Supervised Classification Challenge: - Input: 17 numerical features from SDSS observations - Output: Categorical classification (Star=2, Galaxy=0, Quasar=1) - Dataset Scale: 250,000 observations with high astronomical data quality - Approach: Non-linear machine learning methods (k-NN and Decision Trees)

    The problem represents a moderately imbalanced classification scenario with approximately 50% galaxies, 38% stars, and 12% quasars, reflecting the natural distribution of observable celestial objects.

    Dataset Overview & Characteristics

    Data Source: Sloan Digital Sky Survey (SDSS)

    The Sloan Digital Sky Survey represents one of astronomy's most comprehensive public datasets, utilizing a dedicated 2.5-meter wide-angle optical telescope at Apache Point Observatory, New Mexico. SDSS has catalogued over three million astronomical objects with both spectroscopic and photometric measurements.

    Feature Architecture Analysis

    Spectroscopic Features (5 filters): - u, g, r, i, z: Ultraviolet through infrared photometric measurements - Physical significance: These represent energy emissions across the electromagnetic spectrum - Classification relevance: Different celestial objects exhibit characteristic spectral signatures

    Positional Coordinates: - ra (Right Ascension), dec (Declination): Celestial positioning system - Impact on classification: Spatial distribution patterns may reveal object clustering

    Technical Metadata: - run, rerun, camcol, field: Survey execution parameters - plate, mjd, fiberid: Observational setup identifiers - Preprocessing implication: These may require removal as non-predictive features

    Critical Classification Feature: - redshift: Wavelength shift measurement - Astronomical importance: Primary indicator of cosmic distance and recession velocity - Expected model behavior: Should emerge as the most important predictive feature

    Data Quality Assessment

    Exceptional Quality Characteristics: - Zero missing values: Professional astronomical data collection standards - No duplicate observations: Each celestial object uniquely identified - Large sample size: 250,000 observations provide robust statistical power - Balanced feature types: Entirely numerical features suitable for algorithmic processing

    Sampling Strategy: For computational efficiency, the tutorial utilizes a 50,000-observation subsample while maintaining class proportions through stratified sampling. This approach preserves statistical relationships while enabling faster iteration during model development.

    Class Distribution Analysis

    Natural Imbalance Reflection: - Galaxies (50.3%): Most abundant observable objects at current survey sensitivity - Stars (38.2%): Limited to Milky Way objects visible from Earth - Quasars (11.5%): Rare, distant objects requiring sensitive detection methods

    This distribution reflects astronomical reality rather than sampling bias, making it an authentic representation of observable celestial object frequencies.

This wide range corresponds to objects from nearby (within our galaxy) to cosmologically distant (early universe). The log-transformation reveals more interpretable patterns, with distinct peaks corresponding to different object classes.

    Photometric Filter Analysis: The five photometric filters (u, g, r, i, z) demonstrate correlated but distinct distributions. High correlations between adjacent wavelength bands (g-r: 0.85, r-i: 0.87) reflect the continuous nature of electromagnetic spectra while maintaining independent information for classification.

    Class-Specific Distribution Patterns

    Redshift as Primary Discriminator: - Stars: Extremely low redshift (z ≈ 0), indicating galactic proximity - Galaxies: Moderate redshift distribution reflecting various cosmic distances
    - Quasars: High redshift tail extending to z > 6, confirming cosmological distances

    Photometric Signatures: Each celestial object type exhibits characteristic spectral patterns: - Stars: Relatively consistent brightness across filters - Galaxies: Complex multi-component light profiles - Quasars: Often point-source appearance with unique spectral features

    Data Preprocessing & Feature Engineering

    Label Encoding Strategy

    Target Variable Transformation: The categorical target variable undergoes label encoding for algorithmic compatibility: - Galaxy → 0 - Quasar → 1 - Star → 2

    Rationale: This numerical encoding preserves class relationships without imposing artificial ordinality, making it suitable for both distance-based and tree-based algorithms.

    Train-Test Split Methodology

    Stratified Sampling Approach: - Split ratio: 90% training, 10% testing - Stratification: Maintains original class proportions in both sets - Random state: Fixed for reproducibility - Result: 45,000 training observations, 5,000 test observations

    Why Stratification Matters: Given the natural class imbalance (especially the smaller quasar class), stratified sampling ensures adequate representation of all celestial object types in both training and validation sets.

    Feature Scaling Considerations

    Algorithm-Specific Requirements:

    k-Nearest Neighbors: - Scaling necessity: High - distance calculations sensitive to feature magnitude differences - Method: StandardScaler normalization (mean=0, std=1) - Impact: Dramatic performance improvement observed

    Decision Trees: - Scaling necessity: Low - tree splits based on threshold comparisons, not distances - Observation: Minimal performance change with/without scaling - Computational benefit: Can skip scaling step for tree-based models

    Dimensionality Reduction Analysis

    Principal Component Analysis (PCA) Evaluation:

    For k-NN with PCA: - Implementation: Full PCA transformation after standardization - Performance impact: Varies depending on variance retention - Computational trade-off: Reduced feature space vs. information loss

    Best Practice: Test PCA impact empirically rather than assuming benefit, as astronomical data often contains meaningful signal across all measured wavelengths.

    Data Quality Validation

    Preprocessing Verification Steps: 1. Missing value confirmation: Zero nulls verified 2. Duplicate detection: No identical observations found 3. Feature distribution assessment: Outliers identified but retained (astronomical extremes often meaningful) 4. Class balance verification: Proportions maintained through stratification

    Feature Selection Outcomes: - Initial features: 17 total - After ID removal: 15 predictive candidates - After metadata filtering: 10 core astronomical measurements - Retention criteria: Class discrimination capability and astronomical relevance

    Model Implementation & Comparison

    Algorithm Selection Rationale

    k-Nearest Neighbors (k-NN): - Strength: Captures local patterns in high-dimensional space - Astronomical relevance: Similar objects should cluster in feature space - Non-parametric advantage: No assumptions about underlying data distribution - Computational consideration: Scales poorly with large datasets

    Decision Trees: - Strength: Hierarchical decision-making mirrors astronomical classification logic - Interpretability: Clear feature importance and decision pathways - Non-linear capability: Handles complex feature interactions - Efficiency: Computationally scalable for large astronomical datasets

    k-NN Performance Analysis

    Without Preprocessing: - Training Accuracy: Moderate performance - Test Accuracy: Declining performance indicating overfitting - Issue: Different feature scales dominate distance calculations

    With Scaling and PCA: - Standardization impact: Significant improvement in classification metrics - PCA considerations: May reduce performance if important spectral information is compressed - Optimal configuration: StandardScaler + selective PCA retention

    Performance Metrics Interpretation: - Precision by class: Varies significantly across celestial object types - Recall patterns: Stars and galaxies generally easier to classify than quasars - F1-scores: Balanced measure showing overall classification effectiveness

    Decision Tree Performance Analysis

    Unscaled Performance: - Training Results: High accuracy (>95%) - Test Results: Strong generalization (>90%) - Class-specific performance: Excellent discrimination across all celestial types

    Scaled Performance: - Observation: Minimal change confirms scale-invariance of tree algorithms - Implication: Preprocessing overhead unnecessary for tree-based methods - Consistency: Both scaled and unscaled versions achieve similar results

    Feature Importance Revelations

    Redshift Dominance: The decision tree analysis reveals redshift as the overwhelmingly important feature (>70% importance), confirming astronomical theory: - Physical basis: Redshift directly correlates with cosmic distance - Classification logic: Distant objects (high redshift) are typically quasars - Tree structure: Redshift forms the root node split

    Secondary Features: - Photometric filters: Provide complementary spectral signature information - Positional coordinates: Minor contribution to classification accuracy - Technical metadata: Negligible importance (correctly filtered out)

    Cross-Validation Assessment

    5-Fold Cross-Validation Results: - Decision Tree: Consistent performance across folds (>90% average) - Stability metric: Low variance between fold performances - Generalization confidence: High reliability for unseen astronomical data

    Overfitting Analysis: - Training vs. Test gap: Minimal for Decision Trees - k-NN concern: Higher overfitting tendency, especially without proper preprocessing - Mitigation strategy: Hyperparameter tuning and regularization

    Algorithm Comparison Summary

    Decision Tree Advantages: 1. Superior accuracy: >90% on test set 2. Computational efficiency: Fast training and prediction 3. Interpretability: Clear decision pathways 4. Scale invariance: No preprocessing overhead 5. Astronomical insight: Confirms redshift importance

    k-NN Limitations: 1. Preprocessing dependence: Requires careful scaling 2. Computational cost: Increases with dataset size 3. Performance ceiling: Lower maximum accuracy achieved 4. Memory requirements: Stores entire training set

    error_by_class = {}
    class_names = ['Galaxy', 'Quasar', 'Star']

    for class_idx, class_name in enumerate(class_names):
        class_mask = y_test == class_idx
        class_errors = error_mask & class_mask

        error_by_class[class_name] = {
            'total_samples': class_mask.sum(),
            'errors': class_errors.sum(),
            'error_rate': class_errors.sum() / class_mask.sum() if class_mask.sum() > 0 else 0
        }

        print(f"\n{class_name} errors:")
        print(f"  Total samples: {class_mask.sum()}")
        print(f"  Errors: {class_errors.sum()}")

    cm = confusion_matrix(y_test, predictions)

    # Most common misclassifications
    misclassifications = []
    for true_class in range(3):
        for pred_class in range(3):
            if true_class != pred_class and cm[true_class, pred_class] > 0:
                misclassifications.append({
                    'true_class': class_names[true_class],
                    'predicted_class': class_names[pred_class],
                    'count': cm[true_class, pred_class],

        class_mask = y_test == class_idx
        class_true = y_test[class_mask]
        class_pred = predictions[class_mask]

        if len(class_true) == 0:
            print(f"  No samples found for {class_name}")
            continue

        # Calculate class-specific metrics
        class_accuracy = accuracy_score(class_true, class_pred)
        class_precision = precision_score(y_test, predictions, labels=[class_idx], 
                                        average=None, zero_division=0)[0]
        class_recall = recall_score(y_test, predictions, labels=[class_idx], 
                                  average=None, zero_division=0)[0]
        class_f1 = f1_score(y_test, predictions, labels=[class_idx],

        print(f"  Sample count: {len(class_true)}")
        print(f"  Accuracy: {class_accuracy:.4f}")
        print(f"  Precision: {class_precision:.4f}")
        print(f"  Recall: {class_recall:.4f}")
        print(f"  F1-Score: {class_f1:.4f}")

        # Analyze misclassifications
        misclassified = class_true != class_pred
        misclassification_rate = misclassified.sum() / len(class_true)

        print(f"  Misclassification rate: {misclassification_rate:.4f}")

        if misclassified.sum() > 0:
            misclassified_as = class_pred[misclassified]
            for target_class in range(3):
                if target_class != class_idx:
                    target_count = (misclassified_as == target_class).sum()
                    if target_count > 0:
                        target_rate = target_count / misclassified.sum()
                        print(f"    {target_count} misclassified as {class_names[target_class]} "
                              f"({target_rate:.2%} of errors)")

        # Feature importance for this class
        if hasattr(best_model, 'feature_importances_'):
            # Get samples correctly classified for this class
            correctly_classified = (y_test == class_idx) & (predictions == class_idx)

            if correctly_classified.sum() > 10:  # Ensure sufficient samples
                # Analyze feature values for correctly classified instances
                correct_features = X_test[correctly_classified]
                feature_means = correct_features.mean()
                feature_stds = correct_features.std()

                print(f"  Characteristic feature values (correctly classified):")
                important_features = np.argsort(best_model.feature_importances_)[-3:][::-1]

                for feat_idx in important_features:
                    feat_name = X_test.columns[feat_idx]
                    feat_mean = feature_means.iloc[feat_idx]
                    feat_std = feature_stds.iloc[feat_idx]
                    print(f"    {feat_name}: {feat_mean:.3f} ± {feat_std:.3f}")

        class_analysis[class_name] = {
            'sample_count': len(class_true),
            'accuracy': class_accuracy,
            'precision': class_precision,
            'recall': class_recall,
            'f1_score': class_f1,
            'misclassification_rate': misclassification_rate
        }

    # Create class-specific performance visualization
    metrics = ['precision', 'recall', 'f1_score']
    class_names_list = list(class_analysis.keys())

    fig, axes = plt.subplots(1, 3, figsize=(15, 5))

    for i, metric in enumerate(metrics):
        metric_values = [class_analysis[cls][metric] for cls in class_names_list]

        bars = axes[i].bar(class_names_list, metric_values, alpha=0.7, 
                          color=['skyblue', 'lightcoral', 'lightgreen'])
        axes[i].set_ylabel(metric.capitalize())
        axes[i].set_title(f'{metric.capitalize()} by Class')
        axes[i].set_ylim(0, 1)
        axes[i].grid(True, alpha=0.3)

        # Add value labels on bars
        for bar, value in zip(bars, metric_values):
            axes[i].text(bar.get_x() + bar.get_width()/2, bar.get_height() + 0.01,
                        f'{value:.3f}', ha='center', va='bottom')

    plt.tight_layout()
    plt.show()
