    Problem Statement & Approach

    The Investment Challenge

    Active portfolio management seeks to outperform broad market indices like the S&P 500 by strategically selecting stocks with higher return potential. Traditional approaches rely on fundamental analysis, technical indicators, or factor models. This tutorial explores an alternative methodology: using network analysis to identify structurally important stocks within the market ecosystem.

    Core Research Question

    Can we construct superior portfolios by identifying stocks based on their network topological position (central vs. peripheral) within correlation-based networks?

    Methodological Foundation

    This approach is based on the research paper "Dynamic portfolio strategy using clustering approach" (arXiv:1608.03058), which proposes that:

    • Central stocks act as market hubs, highly connected to many other stocks, reflecting broad market movements

    • Peripheral stocks occupy edge positions in the network, potentially offering diversification benefits

    • Network topology metrics can identify these structural positions more systematically than traditional correlation analysis alone

    Implementation Workflow

    Phase 1: Historical Network Construction (2011-2020)

    • Collect daily price data for all S&P 500 components

    • Compute log returns to ensure statistical properties suitable for analysis

    • Generate correlation matrices for each year

    • Apply Minimum Spanning Tree (MST) filtering to eliminate redundancy

    • Track network evolution over time

    Phase 2: Centrality-Based Stock Selection (2011-2020)

    • Calculate multiple centrality measures on the filtered network

    • Identify top-n central stocks (high connectivity, hub-like behavior)

    • Identify top-n peripheral stocks (low connectivity, diversified positions)

    Phase 3: Portfolio Performance Simulation (2021)

    • Construct equal-weighted portfolios from selected stocks

    • Simulate performance over 2021

    • Compare against S&P 500 benchmark returns

    Why This Matters

    Traditional portfolio theory focuses on pairwise correlations and variance-covariance matrices. Network analysis adds a structural dimension, revealing:

    • Which stocks serve as market connectors vs. isolates

    • How market structure changes during crisis vs. stable periods

    • Whether topological position predicts future performance

    Log Returns Computation

    Why Log Returns Instead of Simple Returns

    Statistical Foundation:

    Stock price movements are better modeled using logarithmic returns rather than simple returns for several reasons:

    1. Time Additivity:

    Log returns can be summed across time periods:

    Log return from t₀ to t₂ = log return(t₀→t₁) + log return(t₁→t₂)

    Simple returns require complex compounding calculations.

    2. Distribution Properties:

    • Simple returns follow a log-normal distribution (skewed, bounded below at -100%)

    • Log returns approximate a normal distribution (symmetric, unbounded)

    • Normal distribution assumptions enable standard statistical tests

    3. Cross-Sectional Analysis:

    When analyzing portfolio of multiple stocks, log returns are approximately additive across securities, simplifying portfolio mathematics.

    Mathematical Formulation

    Log Return Calculation:

    r_t = ln(P_t) - ln(P_{t-1}) = ln(P_t / P_{t-1})

    Variable Definitions:

    • r_t = log return at time t

    • P_t = price at time t

    • P_{t-1} = price at previous time period

    • ln = natural logarithm

    Annual Return Segmentation

    The analysis computes log returns separately for each calendar year (2011-2020). This segmentation serves two purposes:

    1. Network Construction:

    Each year produces an independent correlation network, allowing observation of structural changes over time.

    2. Market Regime Analysis:

    Different years represent different market conditions:

    • High correlation years (2011, 2020): Crisis periods where most stocks move together

    • Low correlation years (2014, 2017): Stable markets with more stock-specific movements

    Interpretation of First-Row NaN Values

    The log return calculation using .shift(1) produces NaN in the first row of each year because there's no prior day within that year to compare against. These values are implicitly ignored in subsequent correlation calculations.

    Design Choice:

    Rather than carrying the last day of the previous year into the next year's calculation, the clean break ensures each year's network is independent. This is appropriate for annual network analysis but might miss information if performing rolling window analysis.

    Correlation Network Construction

    From Returns to Relationships

    Correlation matrices transform individual stock returns into a network representation where:

    • Nodes: Individual stocks (e.g., AAPL, MSFT, JPM)

    • Edges: Correlation strength between stock pairs

    • Edge weights: Correlation coefficient (-1 to +1)

    Correlation as Network Edges

    Interpretation:

    • ρ ≈ +1: Stocks move together (positive correlation)

    • ρ ≈ 0: Stocks move independently

    • ρ ≈ -1: Stocks move opposite (negative correlation, rare in equity markets)

    Network Implication:

    A fully connected network where every stock connects to every other stock, with edge weights proportional to correlation strength.

    Year-by-Year Network Evolution

    The heatmap visualizations reveal distinct patterns:

    High Correlation Years (2011, 2020):

    • Predominantly yellow/red colors across the matrix

    • Indicates system-wide co-movement

    • Interpretation: During crises, diversification breaks down as "everything falls together"

    • Network structure: Dense, highly interconnected

    Low Correlation Years (2014, 2017):

    • More blue/green colors, heterogeneous patterns

    • Indicates stock-specific behavior dominates

    • Interpretation: Stable markets allow company fundamentals to differentiate performance

    • Network structure: More modular, distinct clusters

    Business Insight

    Risk Management Perspective:

    The temporal variation in correlation has profound implications:

    • Tail Risk: Historical low-correlation assumptions fail during crises

    • Portfolio Diversification: Benefits that exist in normal times disappear when needed most

    • Dynamic Hedging: Correlation-based strategies must account for regime changes

    Network Analysis Advantage:

    Traditional portfolio theory often assumes stable correlations. Network visualization immediately reveals when this assumption breaks down, potentially providing early warning signals of market stress.

    Fully Connected Network Problem

    Creating a graph directly from the correlation matrix produces a fully connected network where every node connects to every other node. This creates several problems:

    1. Information Overload:

    With 400+ stocks, this produces 80,000+ edges, making visualization and analysis intractable.

    2. Redundancy:

    Many weak correlations add noise without information.

    3. Computational Cost:

    Centrality measures become expensive on dense graphs.

    Solution: Apply filtering techniques to extract the most important relationships while preserving network structure. This is where Minimum Spanning Tree (MST) filtering becomes essential.

    MST Filtering & Graph Analysis

    The Minimum Spanning Tree Approach

    Definition:

    A Minimum Spanning Tree is a subset of edges that:

    • Connects all nodes (stocks) without cycles

    • Minimizes the total edge weight sum

    • Contains exactly (n-1) edges for n nodes

    Application to Stock Networks:

    By converting correlation to distance and finding the MST, we:

    • Reduce 80,000+ edges to just 400 edges

    • Preserve the most significant relationships

    • Create an interpretable network structure

    • Enable visualization and analysis

    Distance Transformation

    Mathematical Conversion:

    d_ij = √(2(1 - ρ_ij))

    Variable Definitions:

    • d_ij = distance between stocks i and j

    • ρ_ij = correlation coefficient between stocks i and j

    Rationale for This Formula:

    • When ρ = 1 (perfect correlation): d = 0 (zero distance, very similar)

    • When ρ = 0 (no correlation): d = √2 ≈ 1.41 (moderate distance)

    • When ρ = -1 (perfect negative correlation): d = 2 (maximum distance, very different)

    This transformation converts correlation (similarity) into distance (dissimilarity), making it suitable for MST algorithms that minimize distance.

    Why MST for Financial Networks

    Theoretical Justification:

    Research in econophysics has shown that MSTs effectively capture:

    • Hierarchical market structure (sectors, industries, companies)

    • Key market relationships while filtering noise

    • Temporal evolution of market organization

    Practical Benefits:

    • Noise Reduction: Eliminates spurious correlations from short-term market movements

    • Structure Preservation: Maintains the most stable, significant relationships

    • Computational Efficiency: Dramatically reduces graph complexity

    Trade-offs:

    MST filtering is aggressive, discarding most edges. Alternative approaches include:

    • Thresholding: Keep correlations above a certain level

    • Planar Maximally Filtered Graph (PMFG): Retain more edges while maintaining planarity

    • Community Detection: Cluster-based filtering

    The choice depends on whether your goal is simplicity (MST) or comprehensive structure (alternatives).

    Visual Network Evolution

    The filtered network visualizations for 2011-2020 reveal:

    Structural Variation:

    No two years produce identical networks, confirming that market structure is dynamic rather than static.

    Star Topology in Crisis Years:

    During 2011 and 2020 (crisis periods), networks tend to show more pronounced hub-and-spoke patterns with a few highly connected central nodes.

    Distributed Topology in Stable Years:

    During 2014 and 2017 (stable periods), the structure appears more distributed with less pronounced hubs.

    Practical Interpretation:

    This suggests that during crises, the market becomes dominated by a few key stocks or sectors, while in stable periods, more stocks behave independently.

    Network Statistics Over Time

    Average Shortest Path Length Analysis:

    This metric measures how many steps (on average) it takes to get from any stock to any other stock through the network.

    Key Observations:

    • 2011-2015: Relatively stable path length (≈6-7)

    • 2016-2017: Significant increase (≈8-9), suggesting more fragmented market structure

    • 2018: Decrease back toward baseline

    • 2020: Increase again during COVID crisis

    Interpretation:

    • Lower values: More centralized market with strong hubs connecting everything

    • Higher values: More distributed market with distinct clusters

    Financial Implication:

    Changes in path length may signal structural market shifts before they're apparent in price movements alone. A sudden increase might indicate emerging market fragmentation or sector divergence.

    Portfolio Construction Using Centrality

    Full-Period Network Construction

    Unlike the year-by-year analysis, portfolio construction uses the entire 2011-2020 period to build a single correlation network. This approach:

    Advantages:

    • More stable estimates based on 10 years of data

    • Captures long-term structural relationships

    • Reduces impact of short-term market noise

    Disadvantages:

    • Assumes stationary market structure (contradicts earlier finding of temporal variation)

    • May miss recent structural shifts

    • Could average out important regime-dependent patterns

    Critical Assessment:

    This is a significant methodological choice with implications for portfolio stability. An alternative approach would use rolling windows or ensemble methods to account for non-stationarity.

    Multiple Centrality Measures

    The analysis computes four different centrality measures, each capturing a different aspect of network importance:

    1. Degree Centrality

    Measures the number of direct connections a stock has.

    High degree stocks:

    • Connect to many other stocks directly

    • Represent broad market exposure

    • Example: HON (Honeywell) shows highest degree centrality

    Interpretation:

    These are the "popular" stocks that correlate with many others, often representing large-cap, diversified industrial companies or broad sector leaders.

    2. Betweenness Centrality

    Measures how often a stock lies on shortest paths between other stocks.

    High betweenness stocks:

    • Act as bridges between different parts of the network

    • Connect otherwise separated clusters

    • Control information flow in the network

    Portfolio Implication:

    These stocks might offer diversification by bridging different market sectors or factors.

    3. Closeness Centrality

    Measures how close a stock is to all other stocks (inverse of average distance).

    High closeness stocks:

    • Can reach all other stocks quickly

    • Positioned near the network center

    • Reflect broad market movements efficiently

    4. Eigenvector Centrality

    Measures importance based on connection quality (being connected to important nodes).

    High eigenvector stocks:

    • Connected to other important stocks

    • Part of the network's core

    • Influenced by and influence market leaders

    Practical Note:

    Eigenvector centrality often identifies blue-chip stocks that form the market's backbone.

    Visualization and Stock Selection

    The bar chart visualization for degree centrality reveals:

    Distribution:

    Most stocks have low degree centrality, with a few clear outliers at the top.

    Top Stocks:

    HON (Honeywell) dominates, suggesting it serves as a market hub connecting many sectors (aerospace, building technologies, industrial).

    Portfolio Construction Logic:

    • Central Portfolio: Select top-10 or top-20 stocks by centrality measures

    • Peripheral Portfolio: Select bottom-10 or bottom-20 stocks by centrality measures

    Expected Behavior:

    • Central Portfolio: Should track the broader market closely, offering stability but limited alpha

    • Peripheral Portfolio: Should show lower correlation with the market, offering diversification and potential for independent performance

    Critical Assessment

    Strengths of the Approach

    Novel Perspective:

    Network analysis provides structural insights that traditional portfolio theory overlooks. The visualization of market topology is particularly valuable for understanding market organization.

    Multi-Metric Analysis:

    Using multiple centrality measures rather than relying on a single metric strengthens the approach by capturing different dimensions of network importance.

    Temporal Analysis:

    The year-by-year network evolution analysis successfully demonstrates that market structure changes over time, particularly during crisis periods.

    Methodological Limitations

    1. Incomplete Analysis

    The notebook stops before completing the portfolio simulation and performance comparison, leaving the core research question unanswered.

    2. Survivorship Bias

    Using the current S&P 500 constituent list for historical analysis excludes failed or delisted companies, potentially overstating historical performance.

    3. Look-Ahead Bias Risk

    If the portfolio is constructed using information from the same period it's tested on (2011-2020 network for 2021 performance), there's a risk of overfitting.

    4. Stationary Assumption Contradiction

    The analysis first demonstrates non-stationary market structure (2011-2020 networks differ), then assumes stationarity by building a single 10-year network for portfolio selection.

    5. Transaction Costs Ignored

    Real portfolio implementation would incur:

    • Trading commissions (minimal with modern brokers)

    • Bid-ask spreads (significant for less liquid stocks)

    • Market impact (especially for larger portfolios)

    • Rebalancing costs (if portfolio composition changes)

    6. Limited Backtesting

    Testing on only 2021 provides insufficient evidence. A robust analysis would:

    • Test on multiple out-of-sample periods

    • Perform rolling window analysis

    • Assess performance across different market regimes

    Alternative Approaches

    1. Dynamic Network Analysis

    Rather than a static 10-year network, use rolling windows to capture evolving market structure.

    2. Community Detection

    Instead of centrality measures, identify stock communities (clusters) and construct portfolios from different communities for diversification.

    3. Risk-Adjusted Optimization

    Combine network metrics with traditional mean-variance optimization rather than using centrality alone.

    4. Factor Integration

    Incorporate fundamental factors (value, momentum, quality) alongside network metrics for a hybrid approach.

    5. Machine Learning Enhancement

    Use network features as inputs to predictive models rather than direct portfolio selection rules.

    Computational Requirements

    Processing Time:

    • Web scraping: <1 minute

    • Price data loading: <1 minute (with pre-saved CSV)

    • Correlation computation: <1 minute

    • MST construction: <1 minute per year

    • Centrality calculations: 1-2 minutes

    Total Runtime: Approximately 15-20 minutes on standard hardware

    Memory Requirements:

    Minimal; 400 stocks × 10 years of daily data ≈ 10MB. Correlation matrices ≈ 20MB.

    Scalability:

    The approach scales poorly to universes beyond 1,000 stocks due to quadratic growth in correlation matrix size. For larger universes, consider:

    • Sector-level analysis first

    • Sparse correlation matrices

    • Approximate algorithms for MST construction

    When This Approach Works Best

    Ideal Conditions:

    • Medium-sized stock universe (100-500 stocks)

    • Liquid, well-established securities

    • Sufficient historical data (5+ years)

    • Periodic rebalancing strategy (e.g., annual)

    • Combination with fundamental screening

    Questionable Conditions:

    • Small stock universe (network structure less meaningful)

    Purpose:

    Transform price data into log returns, which have superior statistical properties for correlation analysis and satisfy assumptions of normality and stationarity.

    Flow - Step by Step:

    Step 1: Time Shift

    What .shift(1) does:

    Moves each row down by 1 position, filling the first row with NaN.

    Visual representation:

    Original:           After .shift(1):
Date    | Price     Date    | Price
--------|------     --------|------
2011-01-03 | 100       2011-01-03 | NaN
2011-01-04 | 102       2011-01-04 | 100

    Purpose: Aligns today's price with yesterday's price in the same row.

    Step 2: Logarithmic Transformation

    Applies natural logarithm element-wise to all prices.

    Step 3: Log Difference

    np.log(snp_500_2011.shift(1)) - np.log(snp_500_2011)

    Subtracts today's log price from yesterday's log price.

    Mathematical Foundation

    Log Return Formula:

    r_t = ln(P_{t-1}) - ln(P_t) = ln(P_{t-1}/P_t)

    Note: The code computes negative log returns (t-1 minus t) instead of (t minus t-1). This is unconventional but doesn't affect correlation calculations since:

    Corr(X, Y) = Corr(-X, -Y)

    Standard log return (should be):

    log_returns_2011 = np.log(snp_500_2011) - np.log(snp_500_2011.shift(1))

    Properties of Log Returns:

    1. Approximate Simple Returns for Small Changes:

    r_log ≈ r_simple for |r_simple| < 0.15

    Example:

    Price: $100 → $105
Simple return: 5%
Log return: ln(105/100) = 4.88%

    2. Time Additivity:

    r_{t₀→t₂} = r_{t₀→t₁} + r_{t₁→t₂}

    Multi-day returns are simply sums of daily returns.

    3. Normality:

    For small time intervals, log returns approximately follow:

    r_t ~ N(μ, σ²)

    This enables use of parametric statistical methods.

    4. Symmetry:

    ln(P₁/P₀) = -ln(P₀/P₁)

    A 10% gain followed by a 10% loss returns to the original price in log space (but not simple returns).

    Why These Design Choices

    Why log returns vs simple returns?

    Simple Returns:

    r_simple = (P_t - P_{t-1}) / P_{t-1}

    Problems:

    • Not symmetric: +50% gain needs -33.3% loss to break even

    • Not additive across time

    • Non-normal distribution (bounded below at -100%)

    • Cross-sectional portfolio returns require weighted averages

    Log Returns:

    r_log = ln(P_t / P_{t-1})

    Advantages:

    • Symmetric: magnitude of gain equals magnitude of loss

    • Time-additive: multi-period returns are sums

    • Approximately normal for short intervals

    • Suitable for statistical inference

    Code Analysis

    Purpose:

    Convert correlation (similarity measure) into distance (dissimilarity measure) suitable for MST algorithms, which minimize total distance.

    Flow:

    Step 1: Correlation Inversion

    1 - return_correlation_2011

    Effect:

    • High correlation (ρ ≈ 1) → Low value (≈0)

    • Low correlation (ρ ≈ 0) → Medium value (≈1)

    • Negative correlation (ρ ≈ -1) → High value (≈2)

    Step 2: Scaling

    2 * (1 - return_correlation_2011)

    Doubles the range to [0, 4].

    Step 3: Square Root

    np.sqrt(2 * (1 - return_correlation_2011))

    Takes element-wise square root, producing final distance matrix.

    Mathematical Foundation

    Distance Formula:

    d_ij = √[2(1 - ρ_ij)]

    Derivation from Angular Distance:

    This formula comes from the angular interpretation of correlation:

    ρ_ij = cos(θ_ij)

    Where θ is the angle between two normalized vectors in n-dimensional space.

    Euclidean distance between unit vectors:

    d² = ||u - v||² = ||u||² + ||v||² - 2u·v
   = 1 + 1 - 2cos(θ)
   = 2(1 - cos(θ))
   = 2(1 - ρ)

∴ d = √[2(1 - ρ)]

    Properties of this metric:

    1. Range:

    ρ = 1  → d = √[2(1-1)] = 0    (identical stocks, zero distance)
ρ = 0  → d = √[2(1-0)] = √2   (uncorrelated, moderate distance)
ρ = -1 → d = √[2(1+1)] = 2    (opposite stocks, maximum distance)

    2. Metric Properties:

    This is a true metric distance, satisfying:

    • Non-negativity: d(x,y) ≥ 0

    • Identity: d(x,y) = 0 ⟺ x = y

    • Symmetry: d(x,y) = d(y,x)

    • Triangle inequality: d(x,z) ≤ d(x,y) + d(y,z)

    3. Preservation of Relationships:

    ρ₁ > ρ₂  ⟺  d₁ < d₂

    Higher correlation → Lower distance (monotonic transformation)

    Why These Design Choices

    Why this specific formula?

    Alternative distance metrics:

    1. Simple inversion:
    d = 1 - ρ

    • Range: [0, 2]

    • Not a proper metric (violates triangle inequality)

    • Simpler but less theoretically justified

    • Exponential transformation:

    d = -log(ρ) for ρ > 0

    • Emphasizes very high correlations

    • Undefined for ρ ≤ 0

    • Less commonly used

    • Absolute difference:

    d = |ρ₁ - ρ₂|

    • Treats positive and negative correlation symmetrically

    • Not appropriate for financial correlations

    The chosen formula is preferred because:

    • Established in econophysics literature

    • Proper metric satisfying triangle inequality

    • Geometric interpretation (angular distance)

    • Appropriate weighting of correlation differences

    Result Structure

    Distance Matrix Properties:

             AAPL  MSFT  JPM   ...
AAPL     0.00  0.84  1.04  ...
MSFT     0.84  0.00  0.92  ...
JPM      1.04  0.92  0.00  ...

    • Symmetric matrix

    • Zero diagonal (stock's distance to itself is 0)

    • All values between 0 and 2

    • Lower values = more correlated stocks

    Impact

    If you change the transformation:

    Use simple distance:

    distance_2011 = 1 - return_correlation_2011

    Effect:

    • MST will still work

    • Different tree structure possible

    • Less theoretically grounded

    Algorithm (Kruskal's):

    1. Sort all edges by weight (distance)

    2. Initialize empty tree

    3. For each edge in sorted order:

    4. If adding edge doesn't create cycle: add it

    5. If it creates cycle: skip it

    6. Stop when tree has n-1 edges

    Result:

    • Same n nodes

    • Exactly n-1 edges (for 400 stocks: 399 edges)

    • Minimum total edge weight

    • No cycles

    • Treats edges as springs

    • Nodes repel each other

    Mathematical Foundation

    MST Definition:

    For graph G = (V, E, w):

    • V = vertices (stocks)

    • E = edges (correlations)

    • w: E → ℝ (weight function, distance values)

    Minimum Spanning Tree T is a subgraph where:

    T = (V, E_T) such that:
1. E_T ⊆ E
2. |E_T| = |V| - 1
3. T is connected (path exists between any two nodes)
4. T is acyclic (no cycles)
5. Σ_{e∈E_T} w(e) is minimized

    Kruskal's Algorithm:

    function Kruskal(G):
    T = ∅
    for each vertex v in G.V:
        MAKE-SET(v)

    for each edge (u,v) in G.E sorted by weight:
        if FIND-SET(u) ≠ FIND-SET(v):
            T = T ∪ {(u,v)}
            UNION(u,v)

    return T

    Time Complexity:

    O(E log E) for sorting edges
+ O(E α(V)) for union-find operations
≈ O(E log V) overall

    For this problem:

    E ≈ 80,000 edges
V ≈ 400 nodes
Time ≈ 80,000 × log(400) ≈ 700,000 operations (~1 second)

    Prim's Algorithm (Alternative):

    function Prim(G, start_vertex):
    T = {start_vertex}
    while |T| < |V|:
        find minimum weight edge (u,v) where u ∈ T, v ∉ T
        add v to T
        add edge (u,v) to MST
    return MST

    NetworkX Implementation:

    Uses Prim's with binary heap for O(E log V) performance.

    Mathematical Foundation

    Shortest Path Length:

    Average Shortest Path Length:

    Where:

    • n = number of nodes

    • The sum is over all pairs of distinct nodes

    For MST with n nodes:

    n = 400 nodes
Number of pairs: 400 × 399 / 2 = 79,800 pairs

    Algorithm (BFS-based):

    function average_shortest_path_length(G):
    total_length = 0
    count = 0

    for each node u in G:
        distances = BFS(G, u)  # Breadth-First Search from u
        for each node v ≠ u:
            total_length += distances[v]
            count += 1

    return total_length / count

    Time Complexity:

    O(n × (n + edges)) = O(n²) for trees (edges = n-1)

    For 400 nodes: 400² ≈ 160,000 operations per graph

    Mathematical Foundation

    1. Degree Centrality:

    C_D(v) = degree(v) / (n - 1)

    Where:

    • degree(v) = number of edges incident to node v

    • n = total number of nodes

    • Normalized to [0, 1]

    Example:

    Node with 10 connections in 400-node network:
C_D = 10 / 399 ≈ 0.025

    2. Closeness Centrality:

    C_C(v) = (n - 1) / Σ_{u≠v} d(v, u)

    Where:

    • d(v, u) = shortest path length from v to u

    • Inverse of average distance

    Interpretation:

    Measures how quickly node can reach all other nodes.

    3. Betweenness Centrality:

    C_B(v) = Σ_{s≠v≠t} (σ_st(v) / σ_st)

    Where:

    • σ_st = number of shortest paths from s to t

    • σ_st(v) = number of those paths passing through v

    Interpretation:

    Measures how often node lies on shortest paths between other pairs.

    4. Eigenvector Centrality:

    Solves eigenvalue problem:

    Ax = λx

    Where:

    • A = adjacency matrix

    • x = eigenvector (centrality scores)

    • λ = largest eigenvalue

    Iterative computation (Power Method):

    x^(t+1) = Ax^(t) / ||Ax^(t)||

    Interpretation:

    Node is important if connected to other important nodes.

    Centrality Comparison

    Use Cases:

    Degree Centrality:

    • Best for: Identifying broadly connected hubs

    • Portfolio application: Stocks representing broad market exposure

    • Example stocks: Industrials, financials with broad sector ties

    Closeness Centrality:

    • Best for: Identifying central market actors

    • Portfolio application: Stocks that reflect overall market quickly

    • Example stocks: Large-cap tech, major indices components

    Betweenness Centrality:

    • Best for: Identifying bridging stocks

    • Portfolio application: Stocks connecting different market sectors

    • Example stocks: Diversified conglomerates, sector bridges

    Eigenvector Centrality:

    • Best for: Identifying elite network members

    • Portfolio application: "Quality" stocks connected to other quality stocks

    • Example stocks: FAANG stocks, blue-chip leaders

    Algorithm Complexity

    Degree Centrality:

    O(n + edges) = O(n) for trees

    Very fast, ~400 operations.

    Closeness Centrality:

    O(n × (n + edges)) = O(n²)

    Requires BFS from each node, ~160,000 operations.

    Betweenness Centrality:

    O(n × edges) for sparse graphs
O(n³) for dense graphs

    Most expensive, ~160,000-400,000 operations.

    Eigenvector Centrality:

    O(iterations × edges)

    Typically converges in 20-50 iterations, ~10,000 operations.

    def compute_all_centralities(graph):
    """
    Compute multiple centrality measures for network analysis.

    Parameters:
    -----------
    graph : nx.Graph
        Network graph

    Returns:
    --------
    pd.DataFrame
        Centrality measures for all nodes
    """
    centralities = {
        'degree': nx.degree_centrality(graph),
        'closeness': nx.closeness_centrality(graph),
        'betweenness': nx.betweenness_centrality(graph),
        'eigenvector': nx.eigenvector_centrality_numpy(graph),
        'pagerank': nx.pagerank(graph),
        'harmonic': nx.harmonic_centrality(graph)
    }

    # Convert to DataFrame
    df = pd.DataFrame(centralities)
    df['stock'] = df.index

    # Add rankings
    for col in centralities.keys():
        df[f'{col}_rank'] = df[col].rank(ascending=False)

    # Add composite score
    df['composite'] = df[[col for col in centralities.keys()]].mean(axis=1)
    df['composite_rank'] = df['composite'].rank(ascending=False)

    return df.sort_values('composite', ascending=False)
