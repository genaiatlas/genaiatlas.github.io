    Problem Context & Objectives

    This tutorial demonstrates a comprehensive approach to predicting hospital length of stay (LOS) using machine learning techniques. The implementation addresses a critical healthcare management challenge: optimizing resource allocation through predictive analytics.

    Business Problem: HealthPlus hospital faces revenue losses and operational inefficiencies due to poor resource allocation of beds, equipment, and staff. The solution involves developing a predictive model to estimate patient length of stay during admission.

    Technical Objective: Build and validate a machine learning model that predicts LOS using patient admission data and initial test results, achieving interpretable results for clinical decision-making.

    Dataset Scope: The analysis uses 500,000 patient admission records with 15 features including demographic data, admission details, health conditions, and hospital resource availability. The target variable is stay duration (3-51 days).

    Practical Applications: The model enables hospitals to proactively plan treatment protocols, allocate staff efficiently, and optimize bed management, potentially reducing both costs and patient mortality through better resource distribution.

    Data Understanding & Overview

    Data Structure Analysis

    The implementation begins with comprehensive data exploration to understand the dataset's characteristics and identify potential modeling challenges.

    Dataset Dimensions: 500,000 rows × 15 columns, representing a substantial sample size that provides statistical power for reliable model development. The large dataset size enables robust cross-validation and generalization testing.

    Data Quality Assessment: Initial inspection reveals no missing values, which simplifies preprocessing but raises questions about data collection completeness. The absence of missing data in healthcare records is unusual and may indicate preprocessing or synthetic data generation.

    Key Findings from Descriptive Statistics: - Target Variable Distribution: LOS ranges from 3-51 days with median of 9 days, showing right-skewed distribution typical in healthcare data - Resource Availability: Average 3 available rooms (0-24 range) and 5 available staff (0-10 range), indicating capacity constraints - Patient Demographics: 74% female patients, 75% aged 21-50, reflecting gynecology department dominance (68% of admissions)

    Data Type Considerations: Mixed data types require careful encoding strategies. The presence of categorical variables like department names and doctor identifiers suggests that feature engineering will be crucial for model performance.

    Limitations Identified: Patient ID analysis reveals repeat admissions (up to 21 times), but the notebook treats each admission independently, potentially missing temporal patterns or patient-specific factors that could improve predictions.

    Data Preprocessing & Preparation

    Categorical Encoding Strategy

    The preprocessing phase implements one-hot encoding using pandas get_dummies with drop_first=True to avoid multicollinearity in regression modeling.

    Encoding Rationale: One-hot encoding is chosen over label encoding because categorical variables (departments, doctors, wards) have no ordinal relationship. The drop_first parameter prevents perfect multicollinearity by creating k-1 dummy variables for k categories.

    Feature Space Expansion: After encoding, the feature space expands significantly due to multiple categorical variables with many levels (9 doctors, 6 wards, 5 departments). This expansion increases model complexity but preserves all categorical information.

    Train-Test Split Implementation: 80-20 split with random state ensures reproducibility. The large dataset size (400,000 training samples) provides sufficient data for reliable parameter estimation and reduces overfitting risk.

    Preprocessing Limitations: The implementation doesn't address potential feature scaling for continuous variables or consider feature selection techniques to reduce dimensionality. Standard scaling might improve convergence in certain algorithms.

    Linear Regression Model Development

    Statistical Modeling Approach

    The implementation uses statsmodels OLS for comprehensive statistical analysis rather than sklearn's implementation, enabling detailed significance testing and assumption validation.

    Model Performance Metrics: - R-squared: 0.84 indicates the model explains 84% of LOS variance - RMSE: ~2.7 days on test data represents typical prediction error - MAE: 2.15 days provides interpretable average prediction error - MAPE: ~19% shows relative prediction accuracy

    Statistical Significance Analysis: Initial model reveals that Insurance, staff_available, and Visitors with Patient show p-values > 0.05, indicating insufficient predictive power at 95% confidence level. These variables are subsequently removed to improve model parsimony.

    Coefficient Interpretation: - Department_surgery: +9.68 days vs. reference (TB&Chest_Disease), reflecting surgical complexity - Department_anesthesia: +6.08 days, indicating severe cases requiring specialized care - Doctor_Dr Simon: +6.14 days vs. reference (Dr Isaac), suggesting surgical specialist handling complex cases

    Model Validation: Train-test performance similarity (RMSE: 2.67 train vs. 2.70 test) indicates good generalization without overfitting, validating the model's reliability for production use.

    Model Diagnostics & Assumption Testing

    Comprehensive Assumption Validation

    The implementation systematically tests linear regression assumptions to ensure statistical validity and reliable inference.

    Multicollinearity Assessment: VIF analysis shows all continuous variables have VIF < 5, confirming no problematic multicollinearity. However, the note about dummy variables having naturally high VIF values highlights a common statistical misconception that the implementation correctly addresses.

    Residual Analysis Results: - Mean of residuals: ~0 (satisfied) - Normality: Histogram and distribution plots confirm approximately normal residuals - Linearity: Residuals vs. fitted values show random scatter without systematic patterns - Homoscedasticity: Goldfeld-Quandt test (p > 0.05) confirms constant variance assumption

    Statistical Test Interpretation: The Goldfeld-Quandt test specifically tests for heteroscedasticity by comparing variances in different data segments. The non-significant result (p > 0.05) supports the homoscedasticity assumption, validating standard error calculations.

    Diagnostic Limitations: While formal tests pass, the implementation could benefit from additional diagnostics like Cook's distance for outlier detection and leverage analysis for influential observations.

        nrows = 2,      # Number of rows of the subplot grid = 2
        sharex = True,  # x-axis will be shared among all subplots
        gridspec_kw = {"height_ratios": (0.25, 0.75)},

    5. Model Building Framework

    Performance Metrics Implementation

    # Function to compute adjusted R-squared
def adj_r2_score(predictors, targets, predictions):
    r2 = r2_score(targets, predictions)
    n = predictors.shape[0]
    k = predictors.shape[1]
    return 1 - ((1 - r2) * (n - 1) / (n - k - 1))

# Function to compute MAPE
def mape_score(targets, predictions):
    return np.mean(np.abs(targets - predictions) / targets) * 100

# Function to compute different metrics to check performance of a regression model
def model_performance_regression(model, predictors, target):
    """
    Function to compute different metrics to check regression model performance

    model: regressor
    predictors: independent variables
    target: dependent variable
    """

    pred = model.predict(predictors)                  # Predict using the independent variables
    r2 = r2_score(target, pred)                       # To compute R-squared
    adjr2 = adj_r2_score(predictors, target, pred)    # To compute adjusted R-squared
    rmse = np.sqrt(mean_squared_error(target, pred))  # To compute RMSE
    mae = mean_absolute_error(target, pred)           # To compute MAE
    mape = mape_score(target, pred)                   # To compute MAPE

    # Creating a dataframe of metrics
    df_perf = pd.DataFrame(
        {
            "RMSE": rmse,
            "MAE": mae,
            "R-squared": r2,
            "Adj. R-squared": adjr2,
            "MAPE": mape,
        },
        index=[0],
    )

    return df_perf

    Mathematical Foundations: - Adjusted R²: 1 - ((1-R²)(n-1)/(n-k-1)) - penalizes model complexity - MAPE: Provides percentage-based error interpretation for business decisions - Comprehensive Framework: Enables consistent model comparison across algorithms

    8. Assumption Testing

    Multicollinearity Diagnostics

    from statsmodels.stats.outliers_influence import variance_inflation_factor

def checking_vif(train):
    vif = pd.DataFrame()
    vif["feature"] = train.columns

    # Calculating VIF for each feature
    vif["VIF"] = [
        variance_inflation_factor(train.values, i) for i in range(len(train.columns))
    ]
    return vif

print(checking_vif(x_train1))

    VIF Interpretation: - Formula: VIF = 1/(1-R²) where R² comes from regressing each predictor against others - VIF < 5 for all continuous variables → No multicollinearity problems - Dummy variables naturally have higher VIF due to categorical structure

    Linear Regression Assumptions

    Assumption 1: Mean of Residuals = 0 

    # Residuals
residual = olsmodel2.resid
residual.mean()
    Result: ≈ 0, confirming unbiased predictions.

    Assumption 2: Normality of Error Terms 

    # Plot histogram of residuals

    Histogram shows approximately normal distribution - assumption satisfied.

    Assumption 3: Linearity 

    # Predicted values
fitted = olsmodel2.fittedvalues

# Plotting Residuals VS Fitted Values

plt.xlabel("Fitted Values")

    Random scatter pattern confirms linearity assumption.

    Assumption 4: Homoscedasticity 

    import statsmodels.stats.api as sms

    Goldfeld-Quandt Test: - H₀: Homoscedastic residuals - H₁: Heteroscedastic residuals
    - Result: p > 0.05 → Fail to reject H₀ → Homoscedasticity confirmed

    Performance Assessment & Limitations

    Critical Model Evaluation

    Strengths of Current Implementation: - Statistical Rigor: Comprehensive assumption testing validates model reliability - Interpretability: Linear coefficients provide clear clinical insights for healthcare professionals - Performance: 84% variance explained with ~2.15-day average error represents clinically useful accuracy - Generalization: Consistent train-test performance indicates robust model behavior

    Significant Limitations:

    Methodological Constraints: - Linear Assumptions: Real healthcare relationships may be non-linear, limiting model flexibility - Feature Selection: P-value based selection may miss interaction effects or non-linear relationships - Temporal Independence: Treating repeat admissions as independent observations ignores patient history patterns

    Data Limitations: - Missing Temporal Features: No consideration of admission day, season, or hospital occupancy trends - Limited Clinical Details: Absence of specific medical procedures, complications, or treatment protocols - Demographic Gaps: Limited socioeconomic indicators that may influence LOS

    Practical Implementation Challenges: - Real-time Prediction: Model requires complete admission data, potentially limiting emergency use cases - Resource Planning: 2-3 day prediction error may be too large for precise bed management - Staff Workflow: Model outputs need integration with existing hospital information systems

    Alternative Approaches Not Explored: - Ensemble Methods: Random Forest or Gradient Boosting might capture non-linear patterns - Time Series Modeling: Sequential admission analysis could improve repeat patient predictions - Survival Analysis: Cox proportional hazards models might better handle censored discharge data

    Computational Requirements: The current implementation is computationally efficient, suitable for batch processing but may require optimization for real-time deployment in high-volume hospitals.

    Recommendation for Improvement: Future iterations should explore ensemble methods, incorporate temporal features, and validate model performance across different hospital units and time periods to ensure broader applicability.
