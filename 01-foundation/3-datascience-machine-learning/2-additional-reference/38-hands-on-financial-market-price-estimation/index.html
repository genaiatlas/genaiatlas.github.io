    Introduction to Kalman Filters

    Kalman Filters represent a powerful state estimation technique developed by Rudolf Kalman in the 1960s. Originally designed for aerospace applications including the Apollo Program and NASA space shuttles, these filters have found extensive application in financial markets for price estimation and signal generation.

    Core Value Proposition

    The fundamental advantage of Kalman Filters is their ability to estimate the state of a process efficiently, supporting estimation of past, present, and future states even when the precise system model is unknown.

    This capability makes them particularly valuable in financial markets where:

    • Direct measurement is impossible: True underlying prices or trends cannot be observed directly

    • Noisy measurements: Market prices contain significant noise from various sources

    • Dynamic systems: Market relationships change over time and require adaptive estimation

    The Two-Step Kalman Process

    Kalman Filters operate through an iterative two-step cycle:

    • Prediction Step: Forecasts the current state based on the previous state and system model

    • Update Step: Adjusts the prediction using new measurement data to produce an optimal estimate

    This predict-update cycle continues indefinitely, continuously refining state estimates as new data arrives.

    Types of Kalman Filters

    Different variants handle various model complexities:

    State Estimator Model Type Assumed Distribution
    Kalman Filter Linear Gaussian
    Extended Kalman Filter Locally Linear Gaussian
    Unscented Kalman Filter Nonlinear Gaussian
    Particle Filter Nonlinear Non-Gaussian

    This tutorial focuses on the standard Kalman Filter suitable for linear systems with Gaussian noise.

    Understanding the Methodology

    Why Kalman Filters for Trading?

    In quantitative trading, Kalman Filters address two critical challenges:

    • Moving Average Replacement: Traditional moving averages require arbitrary window length selection, risking overfitting. Kalman Filters adapt automatically without fixed windows.

    • Dynamic Hedge Ratio Estimation: Mean-reverting strategies require continuously updated hedge ratios. Kalman Filters provide real-time coefficient estimates that adapt to structural market changes.

    Workflow Logic

    Stage 3: Returns Analysis

    • Converts price-based analysis to returns framework

    Kalman Filter as Moving Average Signal

    Implementation Purpose

    This section implements a Kalman Filter to estimate the rolling mean of MSFT stock prices from January 2021 to January 2022. The goal is to demonstrate how Kalman Filters can replace traditional moving averages for trend estimation without requiring window length specification.

    Methodology Rationale

    Traditional moving averages require selecting a lookback window (e.g., 30, 60, 90 days). This choice is arbitrary and risks overfitting to historical data. The Kalman Filter approach:

    • Assumes mean evolves as random walk: The true mean changes slowly over time with small random variations

    • No window length needed: The filter weighs all past observations, automatically giving more weight to recent data

    • Adaptive uncertainty: The filter tracks its own confidence and adjusts accordingly

    Key Results Interpretation

    The comparison reveals important performance characteristics:

    Responsiveness:

    • Kalman estimate reacts more quickly to price changes than 60 or 90-day moving averages

    • Maintains smoother trajectory than the 30-day moving average

    • Balances lag reduction with noise filtering

    Tracking Performance:

    • The Kalman estimate follows actual price movements closely while filtering short-term noise

    • During the zoomed 200-day window, the Kalman line provides superior tracking compared to fixed-window averages

    • Particularly effective during trending markets where rapid adaptation is valuable

    Practical Trading Implications

    For momentum trading strategies using moving average crossovers:

    • Signal Generation: The Kalman estimate can serve as a single adaptive trend indicator

    • Reduced Lag: Faster response to genuine trend changes improves entry and exit timing

    • Parameter Risk: Eliminates the need to optimize and backtest multiple window lengths

    Honest Limitations

    Overfitting Risk:

    • While eliminating window length selection, Kalman Filters introduce other parameters (transition covariance, observation covariance, initial state)

    • These parameters still require careful selection and can be overfit to historical data

    Computational Complexity:

    • More computationally intensive than simple moving averages

    • Requires matrix operations that scale with state dimensionality

    Assumptions:

    • Assumes Gaussian noise and linear state evolution

    • May underperform in markets with regime changes or non-Gaussian behavior

    Dynamic Linear Regression for Beta Estimation

    Implementation Purpose

    This section extends Kalman Filters to estimate time-varying regression coefficients. Specifically, we model the relationship between MSFT returns and S&P 500 returns as:

    MSFT_price ≈ α + β × SPY_price

    where α (alpha) and β (beta) evolve over time rather than remaining constant.

    Why Dynamic Coefficient Estimation Matters

    Static ordinary least squares (OLS) regression assumes parameters remain constant over the entire dataset. This assumption fails in financial markets where:

    • Structural changes occur: Company fundamentals, market conditions, and correlations shift

    • Risk relationships evolve: Beta (systematic risk) changes with business operations and market regimes

    • Hedge ratios decay: Mean-reversion strategies need current, not historical, hedge ratios

    Kalman State Space Formulation

    The Kalman Filter treats (β, α) as the hidden state:

    • State evolution: Parameters follow random walk with small variations (transition covariance = 0.001)

    • Observation model: Observed MSFT price = β × SPY_price + α + noise

    • Measurement uncertainty: Observation covariance set to 2 (arbitrary units based on price scale)

    Results Interpretation: Price-Based Regression

    Slope (Beta) Evolution:

    The beta coefficient shows notable time variation, generally ranging between 0.8 and 1.4. Key observations:

    • Gradual trends: Beta doesn't jump erratically but shows smooth evolution

    • Market regime sensitivity: Beta increases during certain periods, indicating heightened systematic risk

    • Divergence from OLS: The black OLS line represents the average relationship, but individual Kalman estimates (colored lines) adapt to local data better

    Intercept (Alpha) Evolution:

    The alpha coefficient exhibits larger magnitude variations, reflecting:

    • Non-systematic returns: Idiosyncratic performance not explained by market movements

    • Measurement units: Alpha is in price units (dollars) rather than percentage returns

    Visual Analysis:

    The scatter plot with colored lines shows how each state estimate fits recent data better than older data. The color gradient (blue to red representing time progression) demonstrates:

    • Recent estimates track recent price relationships more accurately

    • The filter adapts to structural changes rather than forcing one relationship across all periods

    Practical Applications

    Beta Hedging:

    For a market-neutral strategy holding $100,000 in MSFT:

    • Current beta of 1.2 suggests shorting $120,000 in SPY

    • As beta evolves, hedge ratio adjusts automatically

    • Eliminates the need for periodic reestimation windows

    Risk Management:

    • Real-time beta tracking improves Value-at-Risk (VaR) calculations

    • Portfolio risk attribution becomes more accurate with time-varying betas

    • Stress testing benefits from understanding how betas change under different conditions

    Returns-Based Analysis

    Transitioning to Returns Framework

    Financial analysis typically uses returns rather than prices because returns are:

    • Stationary: More suitable for statistical modeling

    • Scale-free: Enables comparison across assets and time periods

    • Additive: Portfolio returns aggregate linearly

    Implementation Approach

    The Kalman Filter is reapplied to percentage returns:

    MSFT_return ≈ α + β × SPY_return

    Key parameter adjustment:

    • Higher transition covariance: Returns exhibit more volatility, requiring delta = 0.01 (vs 0.001 for prices)

    • Lower observation covariance: Returns have tighter typical ranges, so observation_covariance = 0.01

    Results Interpretation

    Beta Evolution in Returns Space:

    The returns-based beta estimate shows:

    • Starting near zero: Initial estimate begins conservative

    • Gradual convergence: Beta increases toward ~0.7-0.9, converging with the OLS estimate

    • Tighter clustering: Returns data shows less dispersion than prices, leading to more stable estimates

    Visual Differences from Price Analysis:

    The scatter plot reveals:

    • More concentrated data: Returns cluster more tightly than price relationships

    • Adaptive tracking: Despite noisier data, the Kalman Filter successfully tracks evolving relationships

    • Comparison with OLS: The black OLS line again shows the average relationship, while colored lines demonstrate time-varying adaptation

    Why Both Analyses Matter

    Price-Based Analysis:

    • Useful for actual position sizing and hedge construction

    • Directly applicable to portfolio value calculations

    • Easier to interpret in dollar terms

    Returns-Based Analysis:

    • Statistically more appropriate for inference

    • Standard approach in academic literature and risk models

    • Enables comparison across different price scales

    Practical Insights for Trading

    Beta Hedging Application:

    Using returns-based beta of 0.8:

    • Long position in MSFT requires 0.8× short position in SPY (by dollar value)

    • More stable than price-based beta for short-term hedging

    • Adjusts for volatility differences between assets

    Signal Quality:

    • Returns-based signals often produce cleaner entry/exit points

    • Less susceptible to non-stationary price drift

    • Better suited for mean-reversion strategies

    Critical Assessment and Limitations

    What Works Well

    Adaptive Estimation:

    • Successfully tracks time-varying parameters without respecification

    • Balances responsiveness and stability through Bayesian updating

    • Eliminates arbitrary window length selection

    Real-Time Capability:

    • Online algorithm processes data sequentially as it arrives

    • No need to rerun entire dataset when new data arrives

    • Suitable for live trading systems with millisecond latency requirements

    Theoretical Foundation:

    • Optimal estimator under Gaussian assumptions (Gauss-Markov theorem)

    • Provides uncertainty quantification through state covariance

    • Rigorous mathematical framework for parameter selection

    Significant Limitations

    Parameter Sensitivity:

    The transition covariance parameter critically affects results:

    • Too small: Filter responds too slowly, missing structural changes

    • Too large: Filter tracks noise, producing unstable estimates

    • Optimal selection: Requires careful tuning, similar to moving average window length

    Computational Requirements:

    • Matrix inversions scale as O(n³) with state dimension

    • Memory requirements grow with state covariance matrices

    • Approximately 10-50× slower than simple moving averages for single-state problems

    Assumption Violations:

    Markets frequently violate Kalman Filter assumptions:

    • Non-Gaussian returns: Fat tails and skewness common in financial data

    • Non-linear relationships: Regime-switching behavior not captured

    • Structural breaks: Sudden parameter jumps poorly handled

    When This Method Works Best

    Ideal Conditions:

    • Smoothly varying parameters with small changes

    • Reasonably linear relationships between variables

    • Sufficient data for parameter convergence (minimum 100 observations recommended)

    • Gaussian or near-Gaussian noise distributions

    Suboptimal Conditions:

    • Regime-switching markets with abrupt changes

    • Very low frequency data (monthly or quarterly)

    • Highly non-linear asset relationships

    • Assets with extreme price spikes or gaps

    Alternative Approaches

    Exponentially Weighted Moving Average (EWMA):

    • Simpler to implement and faster to compute

    • Single decay parameter easier to interpret

    • Consider when computational efficiency is critical

    Rolling Window Regression:

    • More robust to non-Gaussian errors

    • Easier to understand and debug

    • Better for discrete regime changes

    Recursive Least Squares (RLS):

    • Similar adaptive properties to Kalman Filter

    • Less assumption-heavy for linear regression problems

    • Consider for purely linear systems

    Extended/Unscented Kalman Filters:

    • Better for non-linear relationships

    • More complex implementation

    • Required when state evolution is non-linear

    Replication Considerations

    Data Requirements:

    • Minimum 250 observations recommended for convergence

    • Daily data preferred; hourly data may be too noisy

    • Ensure proper handling of weekends, holidays, and market closures

    Parameter Selection:

    Initial values used in this tutorial:

    • Transition covariance: 0.001 (prices), 0.01 (returns)

    • Observation covariance: 1-2 (prices), 0.01 (returns)

    These values are not universal and should be validated for different assets and time periods.

    Implementation Risks:

    • Numerical instability with poorly conditioned covariance matrices

    • Divergence if observation covariance set too low

    • Requirement for positive definite covariance matrices

    Kalman Filter Implementation

    from pykalman import KalmanFilter

    Purpose:

    Imports the KalmanFilter class, which provides the core filtering functionality.

    Key Methods Used:

    • filter(): Runs forward Kalman filter pass, returning state means and covariances

    • Constructor parameters: Define the state space model structure

    Mathematical Foundation:

    The KalmanFilter class implements the standard Kalman equations:

    Prediction:

    x̂ₖ|ₖ₋₁ = Fₖ x̂ₖ₋₁|ₖ₋₁
Pₖ|ₖ₋₁ = Fₖ Pₖ₋₁|ₖ₋₁ Fₖᵀ + Qₖ

    Update:

    Kₖ = Pₖ|ₖ₋₁ Hₖᵀ(Hₖ Pₖ|ₖ₋₁ Hₖᵀ + Rₖ)⁻¹
x̂ₖ|ₖ = x̂ₖ|ₖ₋₁ + Kₖ(zₖ - Hₖ x̂ₖ|ₖ₋₁)
Pₖ|ₖ = (I - Kₖ Hₖ) Pₖ|ₖ₋₁

    Variable Definitions:

    • x̂ₖ|ₖ = state estimate at time k given observations up to k

    • Pₖ|ₖ = state covariance at time k

    • Fₖ = transition matrix (how state evolves)

    • Hₖ = observation matrix (how state relates to observations)

    • Qₖ = process noise covariance

    • Rₖ = observation noise covariance

    • Kₖ = Kalman gain (optimal weight for new observation)

    Kalman Filter Construction for Moving Average

    Defining the Kalman Filter Model

    kf = KalmanFilter(transition_matrices = [1],
                  observation_matrices = [1],
                  initial_state_mean = 0,
                  initial_state_covariance = 1,
                  observation_covariance=1,
                  transition_covariance=.01)

    Purpose:

    Constructs a one-dimensional Kalman Filter to estimate the rolling mean of stock prices.

    Mathematical Model:

    This implements the state space representation:

    State Equation:

    μₜ = μₜ₋₁ + wₜ

    Observation Equation:

    yₜ = μₜ + vₜ

    Variable Definitions:

    • μₜ = hidden state (true rolling mean at time t)

    • yₜ = observation (actual price at time t)

    • wₜ ~ N(0, Q) = process noise with covariance Q = 0.01

    • vₜ ~ N(0, R) = observation noise with covariance R = 1

    Parameter Analysis:

    transition_matrices = [1]:

    • Defines how state evolves from t-1 to t

    • Value of 1 means: μₜ = 1 × μₜ₋₁ + noise

    • Implements random walk model for the mean

    observation_matrices = [1]:

    • Defines relationship between state and observation

    • Value of 1 means: price = 1 × mean + noise

    • Direct observation model (state equals expected observation)

    initial_state_mean = 0:

    • Starting guess for the mean

    • Value of 0 is arbitrary; filter corrects this quickly

    • Actual starting price around $217, so this is far off

    initial_state_covariance = 1:

    • Uncertainty in initial guess

    • Low value (1) indicates some confidence despite being wrong

    • Filter increases this internally during early iterations

    observation_covariance = 1:

    • Expected variance of price observations around true mean

    • Set to 1 (arbitrary units)

    • Ratio to transition_covariance matters more than absolute value

    transition_covariance = 0.01:

    • Expected variance of changes in true mean

    • Small value (0.01) means mean changes slowly

    • Ratio Q/R = 0.01/1 = 0.01 determines filter responsiveness

    Design Rationale:

    The ratio of transition_covariance to observation_covariance (0.01) determines how much the filter trusts the model versus observations:

    • Small ratio (0.001): Trust model more, smoother estimate, slower adaptation

    • Large ratio (0.1): Trust observations more, noisier estimate, faster adaptation

    • Chosen ratio (0.01): Balanced approach

    Impact of Parameter Changes:

    Increasing transition_covariance to 0.1:

    • Filter tracks price more closely

    • Estimate becomes noisier

    • Similar to shorter moving average window

    Decreasing transition_covariance to 0.001:

    • Filter produces smoother estimate

    • Slower response to trend changes

    • Similar to longer moving average window

    Running the Filter

    state_means, _ = kf.filter(msft_price.values)

    Purpose:

    Applies the Kalman Filter to the price series, computing optimal state estimates at each time step.

    Method Details:

    filter() performs forward pass only (real-time filtering):

    • Processes observations sequentially from t=1 to t=T

    • At each step, updates state estimate based on new observation

    • Returns both state means and state covariances

    Return Values:

    • state_means: Array of state estimates at each time point

    • _ : State covariances (discarded here using underscore)

    Flow:

    1. Initialize state with initial_state_mean = 0

    2. For each observation in msft_price.values:

    3. Predict next state: μₜ|ₜ₋₁ = μₜ₋₁|ₜ₋₁

    4. Calculate Kalman gain: Kₜ = Pₜ|ₜ₋₁ / (Pₜ|ₜ₋₁ + R)

    5. Update estimate: μₜ|ₜ = μₜ|ₜ₋₁ + Kₜ(yₜ - μₜ|ₜ₋₁)

    6. Update covariance: Pₜ|ₜ = (1 - Kₜ) Pₜ|ₜ₋₁

    7. Return array of all μₜ|ₜ estimates

    Mathematical Simplification:

    For this one-dimensional case with F=H=1, the Kalman gain simplifies to:

    Kₜ = Pₜ|ₜ₋₁ / (Pₜ|ₜ₋₁ + R)

    This represents the weight given to new observations versus the prediction.

    Alternative Method:

    smooth() performs forward-backward pass (batch processing):

    state_means, _ = kf.smooth(msft_price.values)

    Smoothing uses future observations to improve past estimates. Not applicable for real-time trading but provides better historical estimates.

    Setting Up Kalman Filter Parameters

    delta = 1e-3
trans_cov = delta / (1 - delta) * np.eye(2)
obs_mat = np.expand_dims(np.vstack([[joined_data['sp500']], 
                                     [np.ones(len(joined_data['sp500']))]]).T, axis=1)

    Purpose:

    Constructs parameter matrices for two-dimensional Kalman Filter estimating [β, α] coefficients.

    Delta Parameter:

    delta = 1e-3:

    • Controls how much parameters (β, α) change per time step

    • Small value (0.001) assumes parameters change slowly

    • Translated to transition covariance through formula

    Transition Covariance Calculation:

    trans_cov = delta / (1 - delta) * np.eye(2):

    Mathematical Derivation:

    For random walk with persistence, the steady-state variance is:

    σ² = δ/(1-δ)

    where δ represents the innovation variance.

    Result:

    trans_cov = [[0.001001, 0       ],
             [0,        0.001001]]

    Diagonal matrix indicating:

    • β and α evolve independently

    • Both have same evolution variance

    • Small values maintain smoothness

    Observation Matrix Construction:

    np.vstack([[joined_data['sp500']], [np.ones(len(joined_data['sp500']))]]):

    Creates 2 × n matrix:

    [[sp500₁, sp500₂, ..., sp500ₙ],
 [1,      1,      ..., 1     ]]

    .T:

    Transposes to n × 2:

    [[sp500₁, 1],
 [sp500₂, 1],
 ...,
 [sp500ₙ, 1]]

    np.expand_dims(..., axis=1):

    Adds dimension for n × 1 × 2 array required by PyKalman.

    Purpose of Observation Matrix:

    Implements the observation equation:

    MSFTₜ = [sp500ₜ, 1] × [β, α]ᵀ + noise
      = β × sp500ₜ + α + noise

    Each row defines how the hidden state [β, α] maps to an observation.

    Constructing the Kalman Filter

    kf = KalmanFilter(n_dim_obs=1, n_dim_state=2,
                  initial_state_mean=[0,0],
                  initial_state_covariance=np.ones((2, 2)),
                  transition_matrices=np.eye(2),
                  observation_matrices=obs_mat,
                  observation_covariance=2,
                  transition_covariance=trans_cov)

    Purpose:

    Configures Kalman Filter for estimating time-varying regression coefficients.

    Dimension Specification:

    n_dim_obs=1:

    • One observation per time step (MSFT price)

    n_dim_state=2:

    • Two state variables [β, α]

    Initial State:

    initial_state_mean=[0,0]:

    • Starting guess: β=0, α=0

    • Arbitrary initialization; filter corrects quickly

    initial_state_covariance=np.ones((2, 2)):

    [[1, 1],
 [1, 1]]

    • High uncertainty in initial estimate

    • Non-diagonal indicates potential correlation

    • Filter refines this during iterations

    State Evolution:

    transition_matrices=np.eye(2):

    [[1, 0],
 [0, 1]]

    • Identity matrix implements random walk

    • βₜ = βₜ₋₁ + noise

    • αₜ = αₜ₋₁ + noise

    Observation Model:

    observation_matrices=obs_mat:

    • Time-varying matrix (different for each observation)

    • Shape: (n, 1, 2) for n observations

    • Defines how state produces observations

    Noise Covariances:

    observation_covariance=2:

    • Variance of MSFT prices around regression line

    • Scalar value (1D observations)

    • Arbitrary units; ratio to transition_covariance matters

    transition_covariance=trans_cov:

    • Already computed as delta/(1-delta) × I

    • Controls parameter smoothness

    Design Trade-offs:

    If observation_covariance too small:

    • Filter trusts observations too much

    • Tracks noise rather than true parameters

    • Potential numerical instability

    If observation_covariance too large:

    • Filter ignores observations

    • Relies too heavily on predictions

    • Slow adaptation to changes

    If transition_covariance too small:

    • Parameters change very slowly

    • Misses structural changes

    • Over-smoothed estimates

    If transition_covariance too large:

    • Parameters fluctuate excessively

    • Noise in parameter estimates

    • Under-smoothed estimates

    Running the Filter and Extracting Results

    state_means, state_covs = kf.filter(joined_data['Adj Close'])

    Purpose:

    Executes Kalman filtering to obtain [β, α] estimates at each time step.

    Return Values:

    state_means:

    • Shape: (n, 2) array

    • Column 0: β estimates (slopes)

    • Column 1: α estimates (intercepts)

    state_covs:

    • Shape: (n, 2, 2) array

    • Covariance matrices at each time step

    • Diagonal elements: Variances of β and α

    • Off-diagonal: Covariances between β and α

    Processing Flow:

    For each time step t=1 to n:

    1. Prediction: Forecast [βₜ, αₜ] from [βₜ₋₁, αₜ₋₁]

    2. Innovation: Compute prediction error: MSFTₜ - (βₜ|ₜ₋₁ × sp500ₜ + αₜ|ₜ₋₁)

    3. Update: Adjust [βₜ, αₜ] using Kalman gain

    4. Store: Save estimates and covariances

    Kalman Gain Interpretation:

    At each step, the gain determines how much to trust:

    • High gain: Large weight on new observation

    • Low gain: Large weight on prediction

    Gain depends on relative uncertainties (state covariance vs observation covariance).

    Computing Returns

    x_r = joined_data['sp500'].pct_change()[1:]

    Purpose:

    Converts price series to percentage return series for statistically appropriate regression analysis.

    Return Calculation:

    pct_change():

    Computes:

    returnₜ = (priceₜ - priceₜ₋₁) / priceₜ₋₁

    [1:]:

    • Removes first element (NaN from pct_change)

    • Ensures both series have same length

    • First return is from day 1 to day 2

    Why Returns Instead of Prices:

    • Stationarity: Returns more stationary than prices

    • Comparability: Returns are scale-free

    • Statistical properties: Returns closer to normal distribution

    • Economic interpretation: Returns represent investment performance

    Resulting Data:

    • x_r: S&P 500 daily returns

    • y_r: MSFT daily returns

    • Length: n-1 (one less than price series)

    • Typical values: -0.05 to +0.05 (-5% to +5%)

    Delta Adjustment:

    delta_r = 1e-2:

    • Returns exhibit more volatility than prices

    • Allows faster parameter adaptation

    Why Larger Delta:

    • Returns change more rapidly day-to-day

    • Requires less smoothing than prices

    • Higher frequency of structural changes in return space

    Same structure as price-based, but using returns:

    [[return₁ˢᵖ⁵⁰⁰, 1],
