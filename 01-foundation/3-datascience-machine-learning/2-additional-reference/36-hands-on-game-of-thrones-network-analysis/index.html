    Introduction & Context

    This tutorial explores network analysis techniques applied to George R.R. Martin's "A Song of Ice and Fire" book series, the literary foundation for HBO's Game of Thrones. Network analysis provides a quantitative framework for understanding complex relationships between characters, revealing hidden patterns in narrative structure that may not be immediately apparent through traditional reading.

    What is Character Co-occurrence Analysis?

    Character co-occurrence analysis treats a narrative as a network where characters are nodes and their interactions form edges. In this dataset, two characters are considered connected if their names appear within 15 words of each other in the text. This proximity threshold captures meaningful interactions while filtering out coincidental mentions.

    Why Network Analysis for Literature?

    Network analysis transforms qualitative literary relationships into quantitative metrics, enabling:

    • Objective identification of protagonist importance beyond subjective interpretation
    • Detection of character communities and alliances that drive plot development
    • Quantification of how character importance evolves across the series
    • Discovery of bridge characters who connect disparate storylines

    This approach has applications beyond literature, including social network analysis, organizational structure analysis, and biological network studies.

    Data Understanding

    Dataset Structure

    The dataset consists of five CSV files, one for each book in the series. Each file represents an undirected graph with three columns:

    • Person 1: First character in the co-occurrence pair
    • Person 2: Second character in the co-occurrence pair
    • Weight: Number of times these two characters co-occur (appear within 15 words of each other)

    Why Undirected Graphs?

    Undirected graphs are appropriate here because co-occurrence is inherently symmetric—if Character A appears near Character B, then Character B appears near Character A. The relationship has no directional component, unlike, for example, a "gives orders to" relationship which would require a directed graph.

    Key Dataset Characteristics:

    After loading and combining all five books, the complete network contains:

    • 2,823 edges: Unique character pair co-occurrences across all books
    • Weight range: 3 to 334 co-occurrences per pair
    • Mean weight: 11.56 (median: 5), indicating right-skewed distribution
    • Maximum connection: Robert Baratheon and Eddard Stark with 334 co-occurrences

    Interpretation of Descriptive Statistics:

    The minimum weight of 3 indicates a data quality threshold—only relationships with at least three co-occurrences are included, filtering noise. The large gap between mean (11.56) and median (5) reveals that while most character pairs have modest interaction, a few central relationships dominate the narrative. The maximum weight of 334 between Robert Baratheon and Eddard Stark makes narrative sense, as these two characters drive the central plot of Book 1 before both exit the story.

    Data Quality Considerations:

    • The 15-word proximity threshold is somewhat arbitrary; different thresholds would yield different networks
    • Co-occurrence frequency doesn't necessarily correlate with relationship importance (a brief but pivotal scene may have fewer mentions than casual interactions)
    • Character name variations (nicknames, titles) may create multiple nodes for the same character if not standardized
    • The analysis treats all books equally, though they vary in length and publication timeline

    Network Construction & Descriptive Analysis

    Creating Graph Objects

    NetworkX graphs are created separately for each book and for the combined dataset using the from_pandas_edgelist() method. This function automatically:

    • Identifies unique nodes (characters) from the Person 1 and Person 2 columns
    • Creates edges between node pairs
    • Assigns edge weights from the weight column
    • Structures the data as an undirected graph object

    Why Separate Graphs for Each Book?

    Maintaining individual book graphs alongside the combined graph enables temporal analysis. We can track how:

    • Character importance shifts as the plot progresses
    • New characters are introduced and established characters fade
    • Network structure evolves with plot developments (deaths, alliances, separations)

    Combined Network Statistics:

    The complete series network contains:

    • 796 nodes: Unique characters across all five books
    • 2,823 edges: Total character co-occurrence relationships
    • Average degree: 7.09 connections per character

    Interpretation:

    An average degree of 7.09 means the typical character directly interacts with approximately 7 other characters. This relatively low connectivity suggests the narrative is composed of multiple semi-independent storylines rather than one fully interconnected plot. This aligns with George R.R. Martin's multi-POV narrative structure, where different characters experience separate but occasionally intersecting story arcs.

    Data Aggregation Methodology:

    When combining books, co-occurrences are summed across the series. If Characters A and B co-occur 10 times in Book 1 and 15 times in Book 2, their combined edge weight is 25. This preserves the cumulative importance of relationships across the narrative.

    Network Density Implications:

    With 796 nodes and 2,823 edges, the network density is quite low (actual edges / possible edges). This sparse connectivity is typical of narrative networks, where each character participates in specific storylines rather than interacting with everyone. Dense networks would suggest implausible levels of character interaction.

    Centrality Measures Analysis

    Centrality measures quantify node importance from different perspectives. This analysis calculates three complementary centrality metrics, each revealing different aspects of character significance.

    Degree Centrality

    What It Measures:

    Degree centrality counts direct connections. For character networks, it represents how many unique characters a given character directly interacts with.

    Top Characters (Combined Series):

    • Tyrion Lannister: Highest degree centrality
    • Jon Snow: Second highest
    • Jaime Lannister: Third highest

    Interpretation:

    Tyrion's consistent position at the top reflects his role as a diplomatic negotiator who navigates multiple factions. Unlike characters confined to single storylines, Tyrion interacts with Lannisters, Starks, wildlings, and various political players. This metric answers: "Who has the broadest social reach?"

    Limitations:

    Degree centrality treats all connections equally—a brief encounter counts the same as a deep relationship. It also doesn't account for the importance of the characters you're connected to (addressed by eigenvector centrality).

    Eigenvector Centrality

    What It Measures:

    Eigenvector centrality considers not just how many connections you have, but how important your connections are. It's recursive—being connected to highly central characters increases your own centrality score.

    Top Characters (Combined Series):

    • Tyrion Lannister: Highest eigenvector centrality
    • Cersei Lannister: Second highest
    • Joffrey Baratheon: Third highest

    Interpretation:

    This ranking highlights power dynamics rather than just connection counts. Cersei and Joffrey rank higher here than in degree centrality because they're connected to politically powerful characters at the center of King's Landing intrigue. This metric answers: "Who is connected to the most important people?"

    Why Different from Degree Centrality:

    A character might have many connections (high degree) but to peripheral characters. Eigenvector centrality downweights such connections. Conversely, being connected to a few extremely central characters (like the king) yields high eigenvector centrality.

    Betweenness Centrality

    What It Measures:

    Betweenness centrality identifies characters who bridge different groups. It calculates how often a character lies on the shortest path between other character pairs.

    Top Character (Combined Series):

    • Jon Snow: Highest betweenness centrality despite lower degree centrality than Tyrion

    Critical Interpretation:

    Jon Snow's top position here is narratively significant. He uniquely bridges the Night's Watch, the Wildlings, and the Northern houses—groups that rarely interact otherwise. Removing Jon from the network would disconnect these communities, disrupting information flow between them.

    Practical Implications:

    High betweenness centrality characters:

    • Control information flow between communities
    • Are critical for network cohesion
    • Serve as bridges between storylines
    • Have strategic importance beyond social popularity

    When Characters Die:

    A character with high betweenness centrality (but low degree centrality) can fragment the network when removed, even though they don't have many connections. This explains why certain character deaths have disproportionate plot impacts.

    Cross-Book Comparison

    Book 1 Dominant Characters:

    • Eddard Stark: Highest degree and eigenvector centrality
    • Robert Baratheon: Second highest
    • Reason: Both drive the central King's Landing plot

    Book 2 Shift:

    • Tyrion Lannister becomes most central
    • Reason: Becomes Hand of the King after Eddard's execution

    Book 5 Patterns:

    • Jon Snow: Highest degree centrality
    • Daenerys: Second highest
    • Stannis Baratheon: Highest betweenness centrality
    • Reason: Jon and Daenerys lead separate major storylines; Stannis connects Northern plots

    Evolution Interpretation:

    These shifts track major plot developments. When Eddard dies, his centrality plummets to zero in subsequent books. New characters rise as they enter the narrative. This temporal analysis reveals how plot structure reshapes the network.

    Choosing the Right Centrality Measure

    Use Degree Centrality when:

    • Identifying characters with broad social reach
    • Finding characters who participate in many interactions
    • Measuring raw connection counts matters

    Use Eigenvector Centrality when:

    • Power dynamics and influence matter
    • Quality of connections outweighs quantity
    • Identifying characters connected to important figures

    Use Betweenness Centrality when:

    • Finding characters who connect separate groups
    • Identifying information brokers
    • Assessing network vulnerability to node removal

    Comprehensive Assessment:

    Analyzing all three measures together provides a complete picture. Tyrion ranks high on all three, confirming his central role. Jon's high betweenness but lower degree reveals his unique structural position. Eddard's Book 1 dominance across all measures explains his narrative importance before his death.

    Interactive Network Visualization

    Visualization transforms abstract network metrics into intuitive visual patterns. This analysis uses Plotly to create interactive graphs where users can explore connections dynamically.

    Visualization Methodology

    Layout Algorithm:

    The spring layout algorithm positions nodes by treating edges as springs—strongly connected nodes pull closer together while weakly connected nodes drift apart. This creates natural clustering where tight communities appear visually grouped.

    Visual Encoding:

    • Node size: Could represent degree centrality (more connections = larger node)
    • Node color: Represents number of connections, using a red-blue color scale
    • Edge thickness: Could represent weight (co-occurrence frequency)
    • Node position: Determined by network structure via spring layout

    Interactive Features:

    • Hover information: Shows character name and connection count
    • Zoom and pan: Explore dense network regions
    • Selection: Isolate portions of the graph

    Filtering Strategy

    Why Filter to Top 50 Characters?

    The complete network with 796 nodes creates visual clutter that obscures patterns. Filtering to the top 50 by degree centrality focuses on narratively significant characters while maintaining key structural features.

    Trade-offs:

    • Advantage: Clearer visualization, faster rendering, focus on main plot
    • Disadvantage: Loses peripheral characters, may break some community structures, removes minor but interesting connections

    Interpretation of Complete Network Visualization

    Key Observations:

    • Central cluster: Tyrion, Jon, Jaime form a densely connected core
    • Peripheral groups: Some characters cluster at edges, suggesting isolated storylines
    • Bridge characters: Visually identifiable as nodes connecting otherwise separate clusters

    What the Visualization Reveals:

    The network is not a single connected blob but rather multiple loosely connected communities. This structure reflects the multi-POV narrative—different character groups experience separate adventures that occasionally intersect.

    Book-by-Book Visual Analysis

    Book 1 Visualization:

    • Central nodes: Eddard Stark and Robert Baratheon dominate the center
    • Tight clustering: House Stark members cluster together
    • Lannister cluster: Cersei, Jaime, Tyrion, Joffrey form another distinct group
    • Interpretation: Two main power centers (Stark and Lannister) with some bridging characters

    Book 2 Visualization:

    • Shift in center: Tyrion moves to network center as Hand of the King
    • Eddard's absence: Notable gap where Eddard was in Book 1
    • Expanded Lannister influence: Lannister cluster grows and centralizes
    • Interpretation: Power consolidation in King's Landing after Eddard's death

    Book 3 Visualization:

    • Jon Snow prominence: Moves from periphery toward center
    • Continuing Tyrion dominance: Remains most connected
    • Stark fragmentation: Stark family members more dispersed than Book 1
    • Interpretation: Plot threads diverging as characters separate geographically

    Book 4 Visualization:

    • Jaime Lannister central: Takes over as most connected character
    • Reduced network density: Fewer tight connections overall
    • Cersei prominence: Strong co-centrality with Jaime
    • Interpretation: Focus narrows to specific storylines

    Book 5 Visualization:

    • Jon Snow and Daenerys co-dominate: Two major separate networks
    • Stannis as bridge: Positioned between northern groups
    • Tyrion's shift: Captured and moved to different storyline
    • Interpretation: Parallel major narratives in the North (Jon) and Essos (Daenerys)

    Visual Pattern Recognition

    Identifying Communities Visually:

    Even without formal algorithms, visualization reveals community structure through spatial clustering. Characters who co-occur frequently pull together, forming visually distinct groups.

    Bridge Character Identification:

    Characters positioned between clusters with connections spanning both groups are visual bridges. These often correspond to high betweenness centrality.

    Temporal Change Visualization:

    Comparing book-by-book visualizations reveals narrative evolution. Characters moving from periphery to center (Jon Snow) or center to periphery (Eddard Stark) reflect changing plot importance.

    Limitations of Network Visualization

    Inherent Challenges:

    • Layout variability: Spring layout has random components; different runs produce different (but equivalent) layouts
    • Occlusion: Overlapping nodes in dense regions hide information
    • Edge crossings: Many edges create visual clutter
    • 3D vs 2D: Forced 2D projection of multidimensional relationships

    Interpretation Cautions:

    • Physical distance in layout doesn't directly correspond to relationship strength
    • Visual centrality approximates but doesn't perfectly match calculated centrality
    • Human perception biases can lead to over-interpreting visual patterns

    Best Practices:

    • Use visualization for exploration, not final analysis
    • Combine visual inspection with quantitative metrics
    • Try multiple layout algorithms to avoid layout-specific artifacts
    • Filter strategically to reveal structure without excessive data loss

    Character Evolution Across Books

    Tracking how character centrality changes across the five-book series reveals narrative structure and plot development. This temporal analysis provides insights into storytelling progression that single-timepoint analysis cannot capture.

    Methodology for Evolution Analysis

    Calculating Evolution:

    For each book, degree centrality is calculated for all characters. These values are then tracked across books for selected important characters, creating time series that show rising and falling importance.

    Why Degree Centrality for Evolution?

    Degree centrality was chosen for temporal tracking because:

    • It directly reflects how many interactions a character has
    • Changes clearly indicate increased/decreased plot involvement
    • It's computationally efficient for multiple recalculations
    • Results are easily interpretable (more connections = more story presence)

    Key Character Trajectories

    Eddard Stark's Arc:

    • Book 1: Highest degree centrality (0.51)
    • Books 2-5: Zero (character deceased)
    • Interpretation: Dramatic drop to zero quantifies his death's impact on the network

    Tyrion Lannister's Arc:

    • Book 1: Third highest degree centrality (0.34)
    • Books 2-4: Consistently highest or second highest (0.40-0.50)
    • Book 5: Slight decline (0.35) as he's captured and separated from power
    • Interpretation: Rising prominence as he becomes Hand of the King, sustained importance throughout

    Jon Snow's Arc:

    • Book 1: Moderate centrality (0.25)
    • Books 2-4: Gradual increase (0.30-0.42)
    • Book 5: Dramatic spike to highest (0.54)
    • Interpretation: Steady rise as he becomes Lord Commander, culminating in Book 5 dominance

    Jaime Lannister's Arc:

    • Book 1: Moderate centrality (0.28)
    • Book 2: Decline (0.18)
    • Book 3-4: Major increase (0.35-0.48)
    • Book 5: Sustained high level (0.38)
    • Interpretation: Initially a supporting character, his captivity reduces prominence in Book 2, then he becomes a major POV character

    Cersei Lannister's Arc:

    • Book 1-2: Moderate centrality (0.25-0.30)
    • Book 3-4: Steady increase (0.35-0.42)
    • Book 5: Decline (0.30)
    • Interpretation: Growing importance as she gains power, then decline as she faces consequences

    Sansa and Arya Stark's Arcs:

    • Book 1: High centrality as they accompany Eddard to King's Landing
    • Books 2-5: Declining centrality as they separate from main power centers
    • Interpretation: Initially important as Stark family members in King's Landing, their importance diminishes as they become more isolated

    Narrative Insights from Evolution

    The Tyrion-Jon Transition:

    Tyrion dominates Books 1-4, but Jon surpasses him in Book 5. This quantifies a qualitative shift readers sense—the narrative focus moving from political intrigue in King's Landing (Tyrion's domain) toward the existential threat from beyond the Wall (Jon's domain).

    Character Death Impact:

    Eddard's centrality dropping to exactly zero in Book 2 demonstrates how network analysis can quantify narrative events. His death doesn't just reduce his importance—it eliminates it entirely, unlike characters who simply reduce their plot involvement.

    Rise of New Protagonists:

    Jon's steady rise from moderate to highest centrality tracks his character development from bastard son to Lord Commander. The gradual increase (rather than sudden spike) suggests sustained character development rather than a single pivotal moment.

    POV Character Advantage:

    Characters who become POV characters typically show centrality increases, as the reader experiences their interactions directly. Jaime's Book 3 spike corresponds to becoming a POV character. This reveals a technical aspect of narrative construction—POV status inherently increases measured co-occurrence.

    Statistical Patterns

    Correlation with Major Plot Events:

    • Eddard's execution: Immediate centrality drop to zero in Book 2
    • Tyrion's appointment as Hand: Centrality increase in Book 2
    • Jon's election as Lord Commander: Gradual centrality increase in Books 3-5
    • Red Wedding (Robb Stark's death): Robb's centrality drops to zero in Book 4

    Stability vs Volatility:

    Some characters (Tyrion) maintain consistently high centrality with minor fluctuations. Others (Jaime, Jon) show more volatile trajectories. Stability suggests continuous plot involvement; volatility suggests episodic importance or major character arc transitions.

    Limitations of Evolution Analysis

    Book Length Variations:

    The five books vary in length (word count and page count), which could affect centrality calculations. A character might have the same number of interactions but lower centrality in a longer book with more characters.

    Publication Gap Effects:

    Books 4 and 5 were written to occur simultaneously (split by geography, not chronology), which creates analytical challenges. Some characters appear in Book 4 but not 5, not because they're less important, but because of the geographical split.

    Survivor Bias:

    Tracking evolution only works for characters who survive. Dead characters' trajectories end abruptly, potentially underestimating their overall series importance if we focus only on final-book metrics.

    Practical Applications

    Predicting Future Importance:

    If the series continued, upward trajectory characters (Jon Snow) would likely remain central in future books, while downward trajectory characters might fade further or experience dramatic plot events.

    Identifying Protagonist Shifts:

    The Tyrion-to-Jon dominance shift suggests the series is moving toward Jon as the ultimate protagonist, a prediction that the TV series partially confirmed.

    Detecting Narrative Structure:

    The fact that multiple characters maintain consistently high centrality (Tyrion, Jaime, Cersei) confirms this is an ensemble narrative rather than a single-protagonist story.

    Community Detection

    Community detection algorithms identify groups of nodes that are more densely connected internally than to the rest of the network. In character networks, communities often correspond to narrative factions, geographical groupings, or shared storylines.

    Louvain Algorithm Methodology

    How Louvain Works:

    The Louvain method is a hierarchical algorithm that optimizes modularity—a metric quantifying how well the network is partitioned into communities. It operates in two phases:

    Phase 1 - Local Optimization:

    • Start with each node in its own community
    • For each node, calculate modularity gain from moving it to each neighbor's community
    • Move the node to the community that maximizes modularity gain (or keep it if no improvement)
    • Repeat until no further improvements possible

    Phase 2 - Network Aggregation:

    • Treat each community as a single "super-node"
    • Create a new network where super-nodes are connected if their constituent nodes were connected
    • Repeat Phase 1 on this aggregated network

    This two-phase process continues until modularity cannot be improved further.

    Why Louvain?

    Louvain is chosen for this analysis because:

    • Fast: Efficiently handles large networks (our 796 nodes)
    • Hierarchical: Can detect communities at multiple scales
    • Unsupervised: No need to specify number of communities in advance
    • Proven: Widely used and validated in network science

    Community Detection Results

    Number of Communities Found:

    The algorithm identified 14 distinct communities across the combined series network (when filtered to top 100 characters).

    What This Number Tells Us:

    Fourteen communities suggest a moderately fragmented narrative—not so many that characters are completely isolated, but not so few that everyone is connected. This aligns with Game of Thrones' structure: multiple major plotlines with some cross-cutting characters.

    Identified Communities and Their Narrative Meaning

    The Dothraki Community (Yellow Nodes):

    • Key Members: Khal Drogo, Daenerys Targaryen, Jorah Mormont, Daario Naharis
    • Narrative Meaning: Daenerys's Essos storyline, geographically and culturally separate from Westeros
    • Why Detected: These characters rarely interact with Westerosi characters, creating a distinct cluster
    • Interpretation: This community spans multiple books as Daenerys's journey continues throughout the series

    The King's Landing Power Structure (Light Purple Nodes):

    • Key Members: Tyrion, Cersei, Tywin, Joffrey, Sansa, Margaery
    • Narrative Meaning: The central political intrigue around the Iron Throne
    • Why Detected: These characters are in close proximity geographically and interact frequently around court politics
    • Interpretation: This is likely the largest community, reflecting King's Landing's centrality to the plot

    The Stark/Northern Alliance (Red Nodes):

    • Key Members: Robb, Catelyn, Brienne, Jaime
    • Narrative Meaning: The Northern rebellion and war storyline
    • Why Detected: United by military alliance and geographical movement together

    Limitations of Community Detection

    Methodological Limitations:

    • Resolution limit: Louvain may miss very small or very large communities
    • Randomness: Algorithm has stochastic elements; different runs may yield slightly different results
    • Hierarchical ambiguity: Communities can exist at multiple scales; algorithm chooses one
    • Hard partitioning: Each node assigned to exactly one community, but real relationships may be fuzzy

    Interpretation Challenges:

    Limitations and Caveats

    Data Quality Issues:

    • 15-word proximity threshold is arbitrary: Different thresholds would yield different networks. No theoretical justification for why 15 words specifically.
    • Name standardization challenges: Characters with multiple names, titles, or nicknames may be represented as separate nodes, artificially fragmenting the network.
    • Missing relationships: Characters who interact significantly but aren't frequently co-mentioned (due to separate POV chapters) may have weak measured connections.

    Methodological Constraints:

    • Co-occurrence ≠ interaction quality: A pivotal 10-word scene may be less "important" by co-occurrence than 100 casual mentions. Frequency doesn't capture significance.
    • Undirected edges lose information: The directionality of relationships (who influences whom) is lost in undirected graphs.
    • Static snapshots: Even temporal analysis treats each book as a static network, losing intra-book evolution.

    Interpretation Challenges:

    • Quantitative doesn't mean complete: Centrality metrics provide one lens on importance, but miss subjective, qualitative dimensions that matter to readers.
    • Narrative structure affects metrics: POV characters automatically get higher co-occurrence because readers experience their scenes directly.
    • Enemies cluster together: Characters who fight frequently may have high co-occurrence, making them appear "allied" in network terms despite being adversaries.

    Computational Considerations:

    • Visualization scalability: Full network visualization (796 nodes) is cluttered; filtering is necessary but loses information.
    • Algorithm stochasticity: Spring layout and Louvain algorithm have random components; results vary slightly between runs.
    • Processing time: Network analysis is fast for this dataset (~800 nodes), but would become computationally expensive for much larger literary corpora.

    Purpose:

    Convert pandas DataFrames into NetworkX Graph objects for network analysis.

    Function Parameters:

    nx.from_pandas_edgelist(
    df,                      # Source DataFrame
    source='Person 1',       # Column name for source nodes
    target='Person 2',       # Column name for target nodes
    edge_attr='weight',      # Column(s) to use as edge attributes
    create_using=nx.Graph()  # Type of graph to create
)

    Parameter Explanations:

    df (DataFrame):

    • Input data containing edge list
    • Each row represents one edge
    • Must contain source and target columns

    source and target (str):

    • Column names specifying the two nodes connected by each edge
    • Order doesn't matter for undirected graphs (Graph vs DiGraph would matter)

    edge_attr (str or list):

    • Column name(s) to store as edge attributes
    • Here, 'weight' column becomes edge weight
    • Accessible later as G[node1][node2]['weight']

    create_using (graph class):

    • nx.Graph(): Undirected graph (edges have no direction)
    • Alternatives: nx.DiGraph() (directed), nx.MultiGraph() (multiple edges between nodes)
    • Why Graph? Co-occurrence is symmetric: if A co-occurs with B, then B co-occurs with A

    Flow:

    1. Function reads DataFrame row by row
    2. For each row:
    3. Extracts node names from 'Person 1' and 'Person 2' columns
    4. Creates nodes if they don't exist
    5. Adds edge between nodes
    6. Assigns weight attribute from 'weight' column
    7. Returns complete Graph object

    Graph Object Structure:

    # After creation, G contains:
G.nodes()  # Set of all character names
G.edges()  # Set of all (character1, character2) pairs
G[char1][char2]  # Dictionary of edge attributes, including 'weight'

    Mathematical Representation:

    A graph G = (V, E) where:

    • V = set of vertices (characters)
    • E = set of edges (character pairs)
    • w: E → ℝ+ is the weight function mapping edges to positive real numbers

    Impact:

    This conversion is critical—all subsequent network analysis operates on Graph objects, not DataFrames. NetworkX provides optimized data structures and algorithms that wouldn't work on raw DataFrames.

    Memory Considerations:

    NetworkX graphs store data internally in nested dictionaries:

    {
    'Tyrion': {'Jon': {'weight': 10}, 'Cersei': {'weight': 25}},
    'Jon': {'Tyrion': {'weight': 10}, 'Daenerys': {'weight': 15}},
    ...
}

    For large networks (100,000+ nodes), this can consume significant memory.

    Design Choice - Separate vs Combined Graphs:

    Creating both individual book graphs (G1-G5) and combined graph (G) enables:

    • Temporal analysis (tracking how metrics change across books)
    • Book-specific visualizations
    • Series-wide aggregate analysis

    Eigenvector Centrality Function

    def eigen_central(G):
    eigen_centrality = nx.eigenvector_centrality(G, weight="weight")
    eigen_centrality_sort = sorted(eigen_centrality.items(), key=lambda x: x[1], reverse=True)
    eigen_centrality_sort = pd.DataFrame.from_dict(eigen_centrality_sort)
    eigen_centrality_sort.columns = ["Character", "EigenVector Centrality"]
    return eigen_centrality_sort

    Purpose:

    Calculate eigenvector centrality, which considers not just connections, but the importance of those connections.

    Flow:

    Line 1: Calculate eigenvector centrality

    eigen_centrality = nx.eigenvector_centrality(G, weight="weight")
    • nx.eigenvector_centrality() computes eigenvector centrality using power iteration
    • weight="weight" parameter uses edge weights in calculation
    • Returns dictionary of centrality scores

    Lines 2-4: Sort and format

    Identical to previous functions—sort by centrality score and convert to DataFrame.

    Mathematical Foundation:

    Eigenvector centrality satisfies:

    x_v = (1/λ) Σ A_vw x_w

Where:
x_v = eigenvector centrality of node v
λ = eigenvalue (scaling factor)
A_vw = adjacency matrix entry (1 if edge exists, 0 otherwise)
x_w = eigenvector centrality of neighbor w

    Matrix Formulation:

    Ax = λx

Where:
A = adjacency matrix
x = eigenvector (centrality scores)
λ = eigenvalue

    This is an eigenvalue problem. The eigenvector centrality is the eigenvector corresponding to the largest eigenvalue of the adjacency matrix.

    Conceptual Interpretation:

    Your centrality = (constant × sum of neighbors' centralities)

    This creates a recursive definition:

    • Being connected to high-centrality nodes increases your centrality
    • High-centrality nodes are those connected to other high-centrality nodes

    Weighted Version:

    When weight="weight" is specified:

    x_v = (1/λ) Σ w_vw x_w

Where w_vw is the edge weight between v and w

    Connections with higher weights contribute more to centrality.

    Algorithm: Power Iteration

    NetworkX uses power iteration to approximate eigenvector:

    1. Start with initial guess: x₀ = [1, 1, ..., 1]
    2. Iterate: x_(k+1) = Ax_k / ||Ax_k||
    3. Repeat until convergence (x_k ≈ x_(k+1))

    Typically converges in 50-100 iterations.

    Impact:

    • Computational complexity: O(n³) worst case, but power iteration is usually O(n·m) where m = edges
    • Requires connected graph: If graph has disconnected components, may fail or produce warnings
    • More sophisticated than degree: Captures network structure beyond simple connection counts

    Why Different from Degree Centrality:

    Example:

    • Character A: Connected to 10 minor characters (high degree, low eigenvector)
    • Character B: Connected to 3 major characters like Tyrion (lower degree, high eigenvector)

    Character B may have higher eigenvector centrality despite lower degree.

    Design Choice - Using Weights:

    Including weight="weight" parameter means:

    • Frequent co-occurrences (high weight edges) count more
    • Better reflects strong vs weak relationships
    • Without weights, all connections treated equally

    Betweenness Centrality Function

    def betweenness_central(G):
    betweenness_centrality = nx.betweenness_centrality(G, weight="weight")
    betweenness_centrality_sort = sorted(betweenness_centrality.items(), key=lambda x: x[1], reverse=True)
    betweenness_centrality_sort = pd.DataFrame.from_dict(betweenness_centrality_sort)
    betweenness_centrality_sort.columns = ["Character", "Betweenness Centrality"]
    return betweenness_centrality_sort

    Purpose:

    Calculate betweenness centrality, identifying characters who serve as bridges between different groups.

    Flow:

    Line 1: Calculate betweenness centrality

    betweenness_centrality = nx.betweenness_centrality(G, weight="weight")
    • Computes shortest-path betweenness centrality
    • weight="weight" treats weights as edge distances (lower weight = longer distance)
    • Returns dictionary of centrality scores

    Mathematical Foundation:

    Betweenness centrality for node v:

    C_B(v) = Σ (σ_st(v) / σ_st)

Where:
σ_st = total number of shortest paths from node s to node t
σ_st(v) = number of those paths that pass through v
Sum is over all pairs s ≠ t ≠ v

    Normalization:

    C_B(v) = (1 / ((n-1)(n-2))) Σ (σ_st(v) / σ_st)

Divided by (n-1)(n-2) = number of possible node pairs (excluding v)

    Conceptual Interpretation:

    Betweenness measures how often a node lies on the shortest path between other nodes:

    • High betweenness = many shortest paths pass through this node
    • Such nodes are "bridges" or "gatekeepers"
    • Removing them increases distances between other nodes

    Algorithm: Brandes' Algorithm

    NetworkX implements Brandes' fast algorithm:

    1. For each source node s:
    2. Compute shortest paths from s to all other nodes
    3. Track how many shortest paths pass through each node
    4. Accumulate counts across all source nodes
    5. Normalize

    Computational Complexity: O(n·m) for unweighted graphs, O(n·m + n²·log n) for weighted

    Weight Interpretation:

    weight="weight" means edge weights represent costs/distances:

    • Higher weight = longer distance (counterintuitive!)
    • NetworkX treats weights as edge lengths when finding shortest paths
    • If you want higher weight = stronger connection, invert weights

    Design Issue:

    For co-occurrence networks, this may be backwards:

    • High co-occurrence weight should mean strong connection
    • But NetworkX treats it as long distance
    • Solution: Could invert weights before calculation:
    # Invert weights for betweenness calculation
for u, v, d in G.edges(data=True):
    d['inv_weight'] = 1.0 / d['weight']

betweenness = nx.betweenness_centrality(G, weight='inv_weight')

    This wasn't done in the original notebook, which may affect results.

    Impact:

    • Identifies bridge characters: Characters connecting separate storylines
    • Different perspective: Character with moderate degree but high betweenness is a crucial connector
    • Network vulnerability: Removing high-betweenness nodes fragments network more than removing high-degree nodes

    Example:

    Jon Snow has highest betweenness because he bridges:

    • Night's Watch ← Jon → Wildlings
    • Night's Watch ← Jon → Northern Lords

    Remove Jon, and these groups disconnect.

    Spring Layout Algorithm:

    Also called Fruchterman-Reingold algorithm:

    1. Treat edges as springs: Connected nodes attract each other
    2. Treat nodes as charged particles: All nodes repel each other
    3. Iterate: Repeatedly apply forces until equilibrium reached

    Mathematical Foundation:

    Attractive force (for connected nodes):

    F_attract(d) = d² / k

Where:
d = current distance between nodes
k = optimal distance constant

    Repulsive force (for all node pairs):

    F_repel(d) = -k² / d

Inverse square relationship

    Algorithm Steps:

    1. Initialize: Place nodes randomly or in circle
    2. For each iteration:
    3. Calculate forces between all node pairs
    4. Update node positions based on net force
    5. Cool temperature (reduce step size)
    6. Stop when positions stabilize

    Parameters (defaults used):

    • k=None: Auto-calculate optimal distance
    • iterations=50: Number of optimization iterations
    • seed=None: Random seed for reproducibility (issue: results vary between runs)

    Purpose:

    Apply Louvain community detection algorithm to identify character groupings.

    Flow:

    Step 1: Import libraries

    import community as community_louvain
    • community is the python-louvain package
    • Renamed to avoid conflicts with generic name

    Step 2: Run Louvain algorithm

    partition = community_louvain.best_partition(G, random_state=12345)

    Parameters:

    • G: NetworkX graph to partition
    • random_state: Seed for reproducibility

    Algorithm Mechanics:

    Phase 1 - Local Moving:

    For each node: 1. Calculate modularity if node stays in current community 2. Calculate modularity if node moves to each neighbor's community 3. Move node to community with highest modularity gain 4. Repeat until no improvement possible

    Phase 2 - Aggregation:

    1. Create new graph where each community is a "super-node"
    2. Super-node weights = sum of internal edges
    3. Edges between super-nodes = sum of edges between their communities
    4. Run Phase 1 on this aggregated graph

    Termination:

    Stop when no modularity improvement possible.

    Modularity Formula:

    Q = (1 / 2m) Σ [A_ij - (k_i k_j) / (2m)] δ(c_i, c_j)

Where:
m = total edge weight
A_ij = adjacency matrix (edge weight between i and j)
k_i = degree of node i
δ(c_i, c_j) = 1 if i and j in same community, else 0

    Interpretation:

    Modularity Q measures:

    • Actual within-community edges - Expected within-community edges if random
    • Q ranges from -1 to 1
    • Q > 0.3 indicates significant community structure
    • Q > 0.7 is very strong structure

    'Cersei-Lannister': 0,
