    What is Clustering?¶

    Clustering is an unsupervised learning task that groups data points into clusters so that points in the same cluster are similar to each other and dissimilar to points in other clusters. Unlike classification, clustering operates without labels, discovering structure directly from the data.

    • Goal: assign each data point to exactly one group (hard clustering) or to groups with probabilities (soft clustering).
    • Outcome: descriptive structure that can reveal segments, communities, or latent themes.

    Back to Top

    Example: Archaeology Dig¶

    Imagine an archaeology site where each artifact’s location is recorded as (east, north) coordinates relative to a marker. Historians suspect three families lived at the site. By clustering the artifact locations, we may recover three spatial groups that correspond to where those families lived and discarded objects.

    Similarity & Distance¶

    Clustering depends on a similarity notion. Common choices use a distance metric \( d(\cdot,\cdot) \) over feature vectors \(\mathbf{x} \in \mathbb{R}^d\).

    • Euclidean: \( d(\mathbf{x},\mathbf{y}) = \lVert \mathbf{x} - \mathbf{y} \rVert_2 \)
    • Manhattan: \( d(\mathbf{x},\mathbf{y}) = \lVert \mathbf{x} - \mathbf{y} \rVert_1 \)
    • Cosine distance: \( d(\mathbf{x},\mathbf{y}) = 1 - \frac{\mathbf{x}\cdot\mathbf{y}}{\lVert\mathbf{x}\rVert\,\lVert\mathbf{y}\rVert} \)

    Choose a distance aligned with the data geometry (e.g., cosine for text embeddings).

    Back to Top

    Clustering vs. Classification¶

    • Classification (supervised): learn a mapping from features to known labels (e.g., family names).
    • Clustering (unsupervised): discover groups with no labels available; the structure is inferred from the data alone.

    Back to Top

    Common Algorithms¶

    🔵 K-means (hard, centroid-based)¶

    Minimizes within-cluster variance (sum of squared distances to cluster centroids). Objective:

    The K-means objective:

    \[ \min_{\{C_k\}_{k=1}^K} \sum_{k=1}^{K} \sum_{\mathbf{x}\in C_k} \bigl\| \mathbf{x}-\boldsymbol{\mu}_k \bigr\|_2^2 \]
    • Fast and scalable; assumes roughly spherical clusters of similar size.
    • Sensitive to initialization and outliers.

    🟢 Hierarchical clustering (agglomerative/divisive)¶

    • Builds a tree (dendrogram) of nested clusters using a linkage: single, complete, average, Ward’s.
    • No need to pre-specify \(K\); choose a cut level on the dendrogram.

    🟠 DBSCAN (density-based)¶

    • Finds clusters as regions of high density separated by low-density regions.
    • Parameters: \(\varepsilon\) (neighborhood radius) and minPts.
    • Detects arbitrary shapes and flags noise; struggles with varying densities.

    🟣 Gaussian Mixture Models (soft clustering)¶

    • Probabilistic model: data from a mixture of Gaussians; assigns soft responsibilities.
    • Learned via EM algorithm; captures elliptical clusters with covariance structure.

    Back to Top

    Choosing the Number of Clusters¶

    • Elbow method: inspect the curve of within-cluster sum of squares vs. \(K\) and look for an “elbow.”
    • Silhouette analysis: prefer \(K\) that maximizes average silhouette score.
    • Domain constraints: business or scientific context may dictate plausible \(K\).

    Back to Top

    Evaluating Cluster Quality¶

    Given a point \(i\), let \(a(i)\) be the mean distance to points in its own cluster, and \(b(i)\) the smallest mean distance to points in another cluster. The silhouette is:

    \[ s(i) = \frac{b(i) - a(i)}{\max\{a(i), b(i)\}} \in [-1, 1]. \]

    • Average \(s(i)\) close to 1 ⇒ well-separated clusters; near 0 ⇒ overlapping; negative ⇒ misassigned.

    Other diagnostics: Calinski–Harabasz, Davies–Bouldin, stability under resampling.

    Back to Top

    Challenges & Pitfalls¶

    • Scale sensitivity: standardize features; otherwise one feature may dominate distance.
    • Non-spherical structure: K-means may fail on elongated or manifold-shaped clusters.
    • Outliers & noise: can skew centroids; use robust methods (DBSCAN, trimming).
    • High dimensionality: distance concentration; consider PCA or UMAP first.
    • Initialization: multiple restarts (K-means++), consensus clustering for robustness.

    Back to Top

    Minimal Python Example¶

    # Minimal clustering demo: K-means and DBSCAN on 2D data
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.cluster import KMeans, DBSCAN
from sklearn.metrics import silhouette_score

# synthetic data
X, y_true = make_blobs(n_samples=600, centers=3, cluster_std=0.75, random_state=42)

# K-means
kmeans = KMeans(n_clusters=3, n_init="auto", random_state=42)
labels_km = kmeans.fit_predict(X)
sil_km = silhouette_score(X, labels_km)

# DBSCAN (tune eps/min_samples for data scale)
db = DBSCAN(eps=0.8, min_samples=5)
labels_db = db.fit_predict(X)
mask = labels_db != -1  # ignore noise for silhouette if needed
sil_db = silhouette_score(X[mask], labels_db[mask]) if mask.any() else float("nan")

print(f"K-means silhouette: {sil_km:.3f}")
print(f"DBSCAN silhouette (excl. noise): {sil_db:.3f}")

    Overview¶

    K-Means Clustering¶

    K-Means Clustering is one of the most popular algorithms in Unsupervised Learning.

    Why K-Means is popular: - Fast runtime: Simple steps and quick computations. - Parallelizable: Can utilize multiple CPU cores or processors. - Easy to implement: Straightforward to understand and code, with minimal parameter tuning.

    Assumptions¶

    • Known K value: The number of clusters \( K \) is specified in advance.
    • Continuous features: Each data point can be represented as a vector of continuous values.

    Example:
    In an archaeology survey, the location of an artifact might be expressed as:

    \[ \mathbf{x} = [\text{east\_distance\_m}, \ \text{north\_distance\_m}] \]

    For example, point \(X_3\) can be represented as:

    \[ X_3 = [1.5, \ 4.2] \]

    Dissimilarity & Distance¶

    Euclidean Distance¶

    For two points \((X_1, Y_1)\) and \((X_2, Y_2)\):

    \[ d = \sqrt{(X_2 - X_1)^2 + (Y_2 - Y_1)^2} \]

    Squared Euclidean Distance¶

    For vectors \(\mathbf{X} = (x_1, x_2, \dots, x_n)\) and \(\mathbf{Y} = (y_1, y_2, \dots, y_n)\):

    \[ d^{2} = \sum_{i=1}^{n} (x_i - y_i)^{2} \]

    In K-Means, using Squared Euclidean Distance produces the same clustering result as Euclidean distance but is computationally more convenient.

    ↩ Back to Top

    Output of K-Means¶

    • Cluster Assignments: Each data point belongs to exactly one cluster.
    • Cluster Centers: For each cluster \(k\), we find a centroid \(\mu_k\).

    Example:
    If \(S_3\) is the set of data points assigned to the cluster with center \(\mu_3\), then:

    \[ S_3 = \{\, \mathbf{x} \mid \mathbf{x} \ \text{is closest to} \ \mu_3 \,\} \]

    ↩ Back to Top

    Points to Note¶

    • K-Means assumes continuous numeric features — categorical “Yes/No” data is not ideal.
    • Requires exact K value beforehand (which is not always known).
    • Not suited for purely binary vectors unless transformed appropriately.

    The K-Means Algorithm¶

    Quick Links¶

    • Euclidean Distance
    • Squared Euclidean Distance
    • Output of K-Means

    ↩ Back to Top| ⇧ Go to Top of This Topic

    K-Means is a subset of general clustering problems in which: - Each data point is represented as a vector of continuous values. - Squared Euclidean Distance is used as the dissimilarity measure.

    ↩ Back to Top

    Objective¶

    The output of K-Means consists of:

    • A set of cluster centers: \( \mu_1, \mu_2, \dots, \mu_k \)
    • A set of assignments of data points to clusters:

    \[ S_k = { \mathbf{x} \ | \ \mathbf{x} \ \text{is closest to} \ \mu_k } \]

    The main goal: Minimize the Global Dissimilarity within clusters.

    ↩ Back to Top

    Global Dissimilarity¶

    • Dissimilarity within a cluster = Sum of squared distances from each point to its cluster center:

    \[ \text{ClusterDissimilarity}(S_k) = \sum_{\mathbf{x} \in S_k} | \mathbf{x} - \mu_k |^2 \]

    • Global Dissimilarity = Sum over all clusters:

    \[ \text{GlobalDissimilarity} = \sum_{k=1}^{K} \sum_{\mathbf{x} \in S_k} | \mathbf{x} - \mu_k |^2 \]

    • Objective Function: Minimize this global dissimilarity.

    ↩ Back to Top

    The K-Means Algorithm (Lloyd’s Algorithm)¶

    Steps:

    1. Initialize cluster centers
    2. Randomly pick \( K \) points from data (Random Initialization)

    3. Or use K-Means++ for better spread.

    4. Repeat until convergence:

    5. Assignment step: Assign each point to the cluster with the closest center:

      \[ \text{Assign}(\mathbf{x}) = \underset{k}{\mathrm{argmin}} \ | \mathbf{x} - \mu_k | \]

    6. Update step: Recalculate each cluster center as the mean of assigned points:

      \[ \mu_k = \frac{1}{|S_k|} \sum_{\mathbf{x} \in S_k} \mathbf{x} \]

    Notes on Efficiency¶

    • Distance computation for each data point is independent → supports Embarrassingly Parallel Computation.
    • Algorithm always converges in finite time (though not necessarily to the global optimum).

    Key Considerations¶

    • K must be known in advance (or determined with methods like the Elbow Method).
    • Works best with continuous numerical features.
    • Sensitive to initialization — K-Means++ helps.

    Evaluation in Supervised vs. Unsupervised Learning¶

    In supervised learning (classification): - We have labeled data. - We split data into training data (with labels) and test data (with labels set aside for evaluation). - The evaluation is straightforward:
    Predict labels for the test data, compare with true labels, and compute the percentage of correct predictions.

    In clustering (unsupervised): - We typically do not have labels. - If we do have access to a ground truth clustering (e.g., in archaeology or manually clustered images), we can compare results. - However, label permutations don’t affect correctness — what matters is whether pairs of points are in the same or different clusters in both our algorithm and the ground truth.

    External Evaluation Measures¶

    When ground truth is available, we can use metrics like: - Rand Index
    - Adjusted Rand Index

    These work by counting: - Pairs of data points that are in the same cluster in both algorithm and ground truth. - Pairs that are in different clusters in both.

    Then they normalize the result for comparison.

    Challenges¶

    • Rarely do we have ground truth in real clustering tasks.
    • Objective function values (like K-Means’ within-cluster sum of squares) let us compare different runs but do not tell us if the clustering is objectively “good.”
    • Evaluation may fail to capture the exact patterns we are looking for.

    Heuristic Approaches¶

    1. Visualization¶

    • Plot the clustering results and visually inspect patterns.
    • Examples:
    • Archaeology clusters (clear groupings by location).
    • Image segmentation (distinguish objects).
    • Topic modeling (group related words and check coherence).

    2. High-Dimensional Visualization Tools¶

    • GGOBI: Useful for finding meaningful 2D projections of high-dimensional datasets.
    • Helpful when the dataset has many features (e.g., health metrics) and is not easily plottable.

    3. Crowdsourced Evaluation¶

    • Use platforms like Amazon Mechanical Turk to get human feedback on cluster quality.
    • Can be expensive in time and money.

    Internal Evaluation Measures¶

    Do not require ground truth.
    Goal: Ensure points in the same cluster are close together, and points in different clusters are far apart.

    Examples: - Silhouette Coefficient: Measures how similar a point is to its own cluster compared to other clusters. - Split-sample validation: Split the dataset, cluster each half, and compare the resulting cluster assignments.

    Summary¶

    • External Evaluation: Needs ground truth (e.g., Rand Index, Adjusted Rand Index).
    • Internal Evaluation: No ground truth needed (e.g., Silhouette Coefficient).
    • Visualization & Tools: Help qualitative assessment.
    • Crowdsourcing: Adds human judgment at a cost.

    Ground Truth Information in Clustering¶

    Definition¶

    In clustering, ground truth information refers to the true, known class labels or actual group memberships of data points.
    It is the reference standard used to evaluate how well a clustering algorithm performs.

    ↩ Back to Top

    Why It Matters¶

    When we perform clustering, the algorithm groups data based on similarity or distance measures without using labels.
    However, if we already have the true labels (ground truth), we can compare them to the predicted clusters to measure accuracy.

    When Ground Truth is Available¶

    • Synthetic datasets: When we generate data with known cluster assignments.
    • Benchmark datasets: Public datasets like Iris, MNIST, or CIFAR-10 have known labels.
    • Pre-labeled business data: E.g., customer segments determined by domain experts.

    ↩ Back to Top

    Evaluation Metrics Using Ground Truth¶

    When ground truth labels are available, clustering performance can be evaluated using external evaluation metrics, such as:

    1. Rand Index (RI)
      Measures the percentage of correct decisions made by the clustering algorithm.
    2. Adjusted Rand Index (ARI)
      Corrects RI for chance grouping.
    3. Normalized Mutual Information (NMI)
      Measures the similarity between predicted clusters and ground truth labels based on information theory.
    4. Fowlkes–Mallows Index (FMI)
      Measures the geometric mean of precision and recall for clustering.
    5. Purity
      Measures the extent to which clusters contain only members of a single class.

    When Ground Truth is NOT Available¶

    If ground truth is unknown, we must rely on internal evaluation metrics (e.g., Silhouette Score, Davies–Bouldin Index) that do not require labels.

    ↩ Back to Top

    Scenario:
    We have data about animals described by physical traits (weight, number of legs, type of covering).
    - Ground Truth: Actual species name (Dog, Cat, Bird, etc.).
    - Predicted Clusters: Grouping from K-Means algorithm.

    Evaluation:
    We can calculate ARI or NMI to see how close the K-Means clusters match the true species categories.

    Overview¶

    We already know about the clustering problem and the particular algorithm for coming up with the solution — K-Means (also known as Lloyd’s Algorithm).

    Now the question is:
    What happens if the output of the K-Means algorithm is not what we expected or wanted?

    This section discusses: - Troubleshooting K-Means - Ways to make K-Means clustering better

    Ensuring Best Output¶

    • Finite possibilities: K-Means eventually stops because there are only a finite number of possible clusterings.
    • Progress condition: The algorithm moves to a new clustering only if it decreases the K-Means objective function.
    • Not always quick: Although K-Means is generally fast, on some datasets it may take longer.

    ↩ Go to Top of This Topic | ↩ Back to Global Top

    Speed-Up Techniques¶

    In K-Means, we normally compute the distance from every data point to every cluster center.

    However, Triangle Inequality can help avoid checking every center.

    Idea:
    If a data point is clearly closer to one cluster center, far-away centers can be skipped in comparisons — improving efficiency.

    ↩ Go to Top of This Topic | ↩ Back to Global Top

    Local vs Global Optimum¶

    • Local Optimum: The point where K-Means stops might not be the minimum possible value of the objective function.
    • Global Optimum: The true minimum global dissimilarity — hard to guarantee in practice.

    ↩ Go to Top of This Topic | ↩ Back to Global Top

    Strategies to Improve Results¶

    1. Multiple Random Initializations¶

    Run K-Means multiple times with different random starting points, then select the result with the lowest global dissimilarity. - Can be parallelized to reduce runtime impact.

    2. Smarter Initialization — K-Means++¶

    Improves centroid initialization by: - Starting with one random centroid. - Selecting subsequent centroids with probability proportional to the squared distance from the nearest existing centroid. - Ensures centroids are well spread apart. - Often improves both accuracy and runtime.

    Alternative Distance Measures¶

    \(L_2\) (Euclidean)¶

    \[ d_{L2}(\mathbf{x}, \mathbf{y}) = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2} \]

    \(L_1\) (Manhattan)¶

    \[ d_{L1}(\mathbf{x}, \mathbf{y}) = \sum_{i=1}^{n} \lvert x_i - y_i \rvert \]
    • With \(L_1\), a K-Means–like procedure becomes K-Medoids (centers are medoids; in 1D the medoid is the median).

    Computing Mean Ratings¶

    Person Alpine Spa Himalayas Hawaii Scuba

    Finding Deviations¶

    The next step is to find the deviation for each person rating from the mean, and the covariance between the 2 destinations, say Himalayas and Hawaii, is the product of the deviation for both the destinations.

    Formula: 

    DEVIATION = (RATING OF PERSON i FOR LOCATION j) - (MEAN-RATING FOR LOCATION j)

    Anne's Deviations: - Alpine Spa: 20 - 11 = 9 - Hawaii: 4 - 8.3 = -4.3 - Himalayas: 26 - 11.7 = 4.3 - Scuba: 0 - 9 = -9

    Covariance Calculation¶

    To find the covariance between 2 destinations, we do the above settings for each person, that is find how much the person's rating deviates from the mean rating and multiply them. For example, the multiplication of Anne's deviation for the Himalayas and Hawaii is -18.49.

    The covariance between, say, Himalayas and Hawaii is the sum of all the multiplications.

    MATRIX    VECTOR    RESULT
[6 2 3]     [1]       [11]

    Original Vector (Blue):     →

    What Makes Eigenvectors Special¶

    But, if the original vector is an eigenvector, we can only see the magnitude change, and the direction does not change.

    Here, the vector (0.85, 0.26, 0.45) is an eigenvector, and 8.2 is the corresponding eigenvalue, as the resulting vector is the same as the original vector, only the magnitude of the resultant vector is 8.2x.

    MATRIX    EIGENVECTOR    EIGENVALUE × EIGENVECTOR
[6 2 3]      [.85]              [.85]
[2 0 1]  ×   [.26]   =   8.2 ×  [.26]
[3 1 2]      [.45]              [.45]

    Visual Representation: 

    Original Eigenvector (Blue):     →
Resultant Vector (Red):          ──→  (same direction, 8.2x longer)

    In some sense, eigenvectors capture the major direction that is inherent in the matrix, and the larger the eigenvalue, the more important the vector.

    A × x = λ × x

    Where: - A = MATRIX - x = EIGENVECTOR
    - λ = EIGENVALUE

    Another point to note here is that, if we have a DxD matrix, then we will have D eigenvectors and eigenvalues. The highest eigenvalue will have a corresponding eigenvector that captures the major direction in the matrix.

    Overview¶

    Graph clustering is a fundamental technique in network analysis that helps identify communities or groups within complex networks. Unlike traditional clustering where data points have explicit features, graph clustering relies solely on the connectivity patterns between nodes. This approach is essential for understanding the structure of social networks, biological systems, web pages, and many other real-world networks.

    The main challenge in graph clustering is to identify dense groups of nodes (clusters) that are well-connected internally but have fewer connections to other clusters. This document explores various methods and criteria for achieving effective graph clustering.

    ↩ Back to Top

    Graph Fundamentals¶

    Nodes and Edges¶

    In graph theory, data points are represented as nodes (also called vertices), and the relationships between them are represented as edges. This is fundamentally different from traditional data analysis where each data point has a set of features.

    Key Components: - Node: Represents a data point in the graph - Edge: Represents a connection or relationship between two nodes

    Edge Weights¶

    Edges can have weights associated with them, where: - Larger weight = Stronger relationship between nodes - Smaller weight = Weaker relationship between nodes

    Network Examples¶

    Common types of networks include: - Social Media Networks: Users connected by friendships or interactions - Web Page Networks: Pages connected by hyperlinks - Biological Networks: Proteins connected by interactions - Transportation Networks: Cities connected by routes

    ↩ Back to Top

    Cluster Definition¶

    What is a Cluster?¶

    A cluster in a graph is an intuitive concept that consists of nodes that are well-connected with each other. The formal definition involves nodes that have many edges between them, creating a dense subgraph.

    Volume and Density¶

    Volume: The number of edges within a cluster Density: Volume per node, which indicates how tightly connected the cluster is

    ↩ Back to Top

    Clustering Criteria¶

    First Criterion: High Density¶

    For a good cluster, we want the density (volume per node) to be large. This ensures that nodes within a cluster are well-connected to each other.

    Second Criterion: Low Inter-cluster Connections¶

    There should be fewer edges between different clusters, ensuring good separation between distinct groups.

    Cut Value¶

    The Cut Value is defined as the number of edges that need to be removed to separate a cluster from the rest of the graph.

    Formula: Cut(C) = number of edges between cluster C and the rest of the graph

    Problems with Simple Cut Value¶

    Using only the cut value as a criterion can be problematic. For example, an outlier node connected by a single edge would have a cut value of 1, but it doesn't represent a meaningful cluster.

    Key Issue: Cut value alone doesn't consider the size of the cluster, leading to poor clustering results.

    ↩ Back to Top

    Advanced Clustering Metrics¶

    Conductance¶

    Conductance balances the cut value with the cluster size by dividing the cut by a measure of volume.

    Formula: 

    Conductance(C) = Cut(C) / min{Volume(C), Volume(V\C)}

    Normalized Cut¶

    Normalized cut is another metric that balances separation and cluster size.

    Formula: 

    Ncut(C) = Cut(C) / [Volume(C) + Volume(V\C)]

    Formula Analysis¶

    In both formulas: - Small volume → Small denominator → Large criterion value - Large volume → Large denominator → Small criterion value

    Optimization Goal: Minimize these criteria to find good clusters

    Characteristics of Good Clusters: - Not too small - Internally well-connected - Well separated from other nodes

    Overview¶

    Spectral clustering is a powerful graph-based clustering method that leverages the magic of eigenvectors to understand the global connectivity structure of graphs. Unlike traditional clustering methods, spectral clustering uses the eigenvalues and eigenvectors of the graph Laplacian matrix to encode structural information about the graph.

    The key insight is that eigenvectors help us find inherent directions in datasets - similar to how PCA uses eigenvectors from covariance matrices to find major directions of variance, spectral clustering uses eigenvectors from the Laplacian matrix to understand graph structure and identify natural clusters.

    Key Question Addressed: How do we compute similarity criteria for graph clustering when nodes don't have inherent feature vectors?

    Answer: We use the spectral properties (eigenvalues and eigenvectors) of the graph Laplacian matrix to create meaningful embeddings and identify cluster structure.

    ↩ Back to Top

    Key Concepts¶

    Graph Laplacian Matrix¶

    The Laplacian matrix is the fundamental mathematical object in spectral clustering. It encodes the connectivity structure of a graph in a matrix format.

    Construction Rules:¶

    • Off-diagonal elements: -1 if there's an edge between nodes i and j, 0 otherwise
    • Diagonal elements: The degree of each node (number of edges connected to that node)

    Example Graph and Laplacian:¶

    Consider a graph with 6 nodes connected as shown in the original document:

    Node 1 2 3 4 5 6
    1 2 -1 -1 0 0 0
    2 -1 2 -1 0 0 0
    3 -1 -1 3 -1 0 0
    4 0 0 -1 3 -1 -1
    5 0 0 0 -1 2 -1
    6 0 0 0 -1 -1 2

    Node Degrees: - Node 1: degree = 2 (connected to nodes 2 and 3) - Node 2: degree = 2 (connected to nodes 1 and 3) - Node 3: degree = 3 (connected to nodes 1, 2, and 4) - And so on...

    ↩ Back to Top

    Eigenvalues and Eigenvectors¶

    From the Laplacian matrix, we compute eigenvalues and their corresponding eigenvectors, sorted in ascending order of eigenvalues.

    Example Eigenvalue Decomposition:¶

    Eigenvalues 0 0.4 3 3 3 4.6
    Eigenvector Components
    Node 1 0.41 -0.46 -0.05 0.71 0.28 0.18
    Node 2 0.41 -0.46 -0.05 -0.71 0.28 0.18
    Node 3 0.41 -0.26 0.10 0.00 -0.57 -0.66
    Node 4 0.41 0.26 0.10 0.00 -0.57 0.66
    Node 5 0.41 0.46 -0.75 0.00 0.16 -0.18
    Node 6 0.41 0.46 0.65 0.00 0.41 -0.18

    Key Insights: - We focus on the smallest and largest eigenvalues - The smallest eigenvalue is always 0 for connected graphs - Each eigenvector has one entry per node, creating a feature representation

    Connected Components¶

    The number of zero eigenvalues directly corresponds to the number of connected components in the graph.

    Example: Graph with 3 Connected Components¶

    • Eigenvalues: [0, 0, 0, 2, 3, 3]
    • Interpretation: Three zero eigenvalues → Three separate connected components
    • This provides immediate insight into graph structure without complex analysis

    Structural Relationships¶

    Second Eigenvector Analysis¶

    The second smallest eigenvector (corresponding to the second smallest eigenvalue) reveals crucial structural information about the graph.

    Key Properties:¶

    • Each node gets a value from the eigenvector
    • Closer nodes in the graph structure receive similar values
    • Values can be color-coded to visualize clustering patterns
    • Natural partitions emerge from the value distribution

    Color Coding Scheme:¶

    • Blue: Lower values in the eigenvector
    • Red: Higher values in the eigenvector
    • Gradient: Intermediate values show smooth transitions

    Color Coding and Partitioning¶

    When nodes are colored based on their eigenvector values:

    1. Structural similarity becomes visually apparent
    2. Natural partitions can be identified (shown as red dotted lines in visualizations)
    3. Cluster boundaries emerge from the eigenvector value distribution
    4. Connected regions tend to have similar colors

    This approach works even when nodes have no inherent features - the structure itself provides the clustering information.

    ↩ Back to Top

    Node Embeddings¶

    Feature Vector Assignment¶

    Since graph nodes typically don't have feature vectors, spectral clustering creates embeddings using eigenvector values.

    Embedding Process:¶

    1. Extract values: Take one value from each eigenvector for each node
    2. Create feature vector: Combine these values into a multi-dimensional representation
    3. Result: Each node now has a feature vector derived from graph structure

    Comparison with PCA:¶

    • PCA: Uses eigenvectors with largest eigenvalues for dimensionality reduction
    • Spectral Clustering: Uses eigenvectors with smallest eigenvalues for clustering

    ↩ Back to Top

    2D Coordinate Mapping¶

    Using the second and third smallest eigenvectors as coordinates creates a 2D embedding of the graph.

    Visualization Benefits:¶

    • Spatial proximity: Connected nodes appear close in the 2D space
    • Cluster identification: Graph clusters become spatial clusters
    • Edge stretch minimization: Connected nodes are positioned to minimize edge length

    Coordinate Assignment:¶

    Node_i_coordinates = (eigenvector_2[i], eigenvector_3[i])

    This creates a natural 2D representation where graph structure is preserved spatially.

    ↩ Back to Top

    Eigenvalue Effects¶

    Small Eigenvalues - Minimizing Edge Stretch¶

    Eigenvectors corresponding to small eigenvalues have a specific optimization goal:

    Behavior:¶

    • Minimize edge stretch: Connected nodes receive similar values
    • Preserve local structure: Nearby nodes cluster together in embedding space
    • Create cohesive clusters: Graph communities become tight spatial groups

    Mathematical Goal:¶

    Minimize: ∑(edges) (value(i) - value(j))²

    Where value(i) and value(j) are the eigenvector values for connected nodes i and j.

    ↩ Back to Top

    Large Eigenvalues - Maximizing Edge Stretch¶

    Eigenvectors corresponding to large eigenvalues behave oppositely:

    Behavior:¶

    • Maximize edge stretch: Connected nodes receive very different values
    • Spread out structure: Connected nodes are placed far apart in embedding
    • Create dispersed layouts: No clear clustering patterns emerge

    Visual Result:¶

    • Nodes appear scattered across the embedding space
    • Connected nodes are positioned far from each other
    • Clustering structure is destroyed

    ↩ Back to Top

    Mathematical Foundation¶

    Edge Distance Formula¶

    The fundamental principle behind spectral clustering involves optimizing edge-based distances:

    Total_Edge_Stretch = ∑(all edges (i,j)) (value(i) - value(j))²

    Where: - value(i) = eigenvector value assigned to node i - value(j) = eigenvector value assigned to node j - The sum is over all edges in the graph

    ↩ Back to Top

    Optimization Principles¶

    Small Eigenvalue Eigenvectors:¶

    • Objective: Minimize total edge stretch
    • Result: Similar values for connected nodes
    • Use case: Clustering and community detection

    Large Eigenvalue Eigenvectors:¶

    • Objective: Maximize total edge stretch
    • Result: Different values for connected nodes
    • Use case: Maximum separation and dispersion

    Why This Works:¶

    1. Graph structure constraint: Eigenvectors must satisfy Laplacian properties
    2. Optimization pressure: Eigenvalue magnitude determines stretch minimization/maximization
    3. Natural clustering: Small eigenvalues automatically group structurally similar nodes

    Applications and Conclusion¶

    Key Insights from Spectral Clustering¶

    1. Structural Information: Eigenvectors encode rich information about graph connectivity
    2. Automatic Feature Creation: No need for predefined node features
    3. Natural Partitioning: Cluster boundaries emerge from the mathematical structure
    4. Scalable Approach: Works with the graph Laplacian regardless of graph size

    Practical Applications¶

    • Social Network Analysis: Finding communities and groups
    • Image Segmentation: Treating pixels as graph nodes
    • Biological Networks: Identifying functional modules
    • Recommendation Systems: Clustering users or items based on interaction graphs

    The method's power lies in its ability to extract clustering information directly from graph structure, making it invaluable for analyzing complex networks where traditional feature-based approaches fall short.

    Overview¶

    Modularity clustering represents a major advancement in community detection algorithms, addressing a key limitation of spectral clustering: the need to pre-specify the number of communities. This method automatically determines both the optimal number of communities and their composition by maximizing a quality metric called the modularity score.

    Key Advantages over Previous Methods:¶

    1. Automatic community counting: No need to specify k in advance
    2. Baseline comparison: Evaluates communities against a random null model
    3. Widely applicable: Successfully used across diverse network types
    4. Predictive power: Can forecast real-world community splits

    Core Innovation:¶

    Modularity clustering compares the actual network structure against a random baseline graph that preserves key properties (node degrees, total edges) while randomizing connections. Communities with significantly more internal connections than expected by chance are considered genuine.

    Mathematical Foundation: 

    Modularity = (Actual internal edges) - (Expected internal edges from random baseline)

    This approach provides both a quality measure and an optimization target for community detection algorithms.

    Modularity Score Fundamentals¶

    Core Concept¶

    The modularity score quantifies how much a proposed community structure deviates from what would be expected in a random graph with the same basic properties.

    Key Components:¶

    • Aij: Adjacency matrix entry (1 if edge exists, 0 otherwise)
    • Pij: Expected probability of edge in baseline random graph
    • Community assignment: Grouping of nodes into distinct clusters

    Quality Principle:¶

    Good communities: Many more internal edges than random expectation
Poor communities: Similar internal edge count to random expectation

    ↩ Back to Top

    Baseline Graph Comparison¶

    The baseline graph serves as a null hypothesis for community structure evaluation.

    Baseline Properties:¶

    Property Original Graph Baseline Graph
    Number of nodes Preserved Same
    Number of edges Preserved Same
    Node degrees Preserved Same
    Edge placement Actual structure Random

    Why This Comparison Works:¶

    1. Controls for graph size: Same number of nodes and edges
    2. Controls for node importance: Preserves degree distribution
    3. Removes structure: Randomizes actual connections
    4. Highlights deviations: Real structure stands out against random background

    ↩ Back to Top

    Edge Calculation Formula¶

    For any proposed community, the modularity contribution is calculated as:

    Modularity_contribution = Σ(i,j in same community) (Aij - Pij)

    Interpretation:¶

    • Positive values: More internal edges than expected (good community)
    • Zero values: Same as random expectation (no community structure)
    • Negative values: Fewer internal edges than expected (anti-community)

    Example Calculation:¶

    # For a community with nodes [1, 2, 3]
actual_edges = A[1,2] + A[1,3] + A[2,3]  # Count actual edges
expected_edges = P[1,2] + P[1,3] + P[2,3]  # Sum expected probabilities
community_modularity = actual_edges - expected_edges

    Expected Baseline Edges¶

    Probability Calculation¶

    The expected number of edges between any two nodes in the baseline graph depends on their degrees and the total graph structure.

    Formula Derivation:¶

    Pij = (degree(i) × degree(j)) / (2 × total_edges)

    Intuition:¶

    • High-degree nodes: More likely to connect to any given node
    • Proportional probability: Connection probability proportional to degree product
    • Normalization: Divided by total possible connections

    ↩ Back to Top

    Degree-Based Formula¶

    Mathematical Justification:¶

    Consider node i with degree di and node j with degree dj: - Node i has di edges to distribute - Node j has dj edges to distribute
    - Total edges in graph = m - Probability that i and j connect = (di × dj) / (2m)

    Example Calculation:¶

    Node i: degree = 3
Node j: degree = 3  
Total edges = 17

Pij = (3 × 3) / (2 × 17) = 9/34 ≈ 0.26 (26% chance)

    Key Insight:¶

    High-degree nodes are expected to connect frequently, so their actual connections are less surprising than connections between low-degree nodes.

    Negative Modularity¶

    When Modularity Goes Negative¶

    Negative modularity occurs when communities have fewer internal edges than expected from a random baseline.

    Causes of Negative Modularity:¶

    1. Bipartite-like structure: Nodes preferentially connect to different types
    2. Anti-clustering patterns: Nodes avoid connecting to similar nodes
    3. Cross-community preferences: Edges span between rather than within groups

    Mathematical Condition:¶

    Modularity < 0  when  Actual_internal_edges < Expected_internal_edges

    Eigenvector-Based Implementation¶

    Modularity Matrix Construction¶

    Instead of directly optimizing modularity, we can use eigenvector analysis on a specially constructed matrix.

    Modularity Matrix Definition:¶

    Modularity_Matrix[i,j] = Aij - Pij

    Where: - Aij: 1 if edge exists between i and j, 0 otherwise - Pij: Expected edge probability from baseline model

    Matrix Properties:¶

    Property Value Significance
    Diagonal Aii - Pii Self-connection adjustment
    Off-diagonal Aij - Pij Edge deviation from expectation
    Symmetry Yes Undirected graph assumption
    Sum 0 Conservation of total edges

    ↩ Back to Top

    Automatic Cluster Number Detection¶

    The "magic of eigenvectors" automatically determines the optimal number of communities.

    Process:¶

    1. Compute eigendecomposition of modularity matrix
    2. Identify positive eigenvalues: Each indicates a potential community dimension
    3. Select largest eigenvalue: Corresponds to strongest community structure
    4. Use corresponding eigenvector: For community assignment

    Why This Works:¶

    • Positive eigenvalues: Indicate genuine community structure (positive modularity)
    • Negative eigenvalues: Indicate anti-community structure (negative modularity)
    • Zero eigenvalues: Indicate random-like structure (no communities)

    Automatic Detection:¶

    eigenvalues, eigenvectors = np.linalg.eigh(modularity_matrix)
n_communities = sum(eigenvalues > 0)  # Count positive eigenvalues
primary_structure = eigenvectors[:, np.argmax(eigenvalues)]  # Largest eigenvalue

    Matrix Laplacian Modularity matrix
    Optimization goal Minimize edge cuts Maximize modularity
    Eigenvector interpretation Smooth transitions Sharp divisions

    Positive-Negative Node Separation¶

    The eigenvector corresponding to the largest eigenvalue provides a natural community division.

    Assignment Rule:¶

    community_1 = [node for node, value in enumerate(eigenvector) if value > 0]
community_2 = [node for node, value in enumerate(eigenvector) if value < 0]

    Why This Works:¶

    1. Optimization principle: Eigenvector maximizes modularity when used for binary division
    2. Mathematical guarantee: Provides optimal 2-community split
    3. Clear threshold: Zero provides natural boundary

    Multi-Community Extension¶

    Hierarchical Division Strategy¶

    For networks with more than 2 communities, modularity clustering uses a recursive binary division approach.

    Standard Approach:¶

    1. Apply modularity clustering to full network → 2 communities
2. Apply modularity clustering to each subcommunity → 4 communities  
3. Continue until no further improvement in modularity
4. Result: Hierarchical community structure

    Decision Criteria:¶

    • Continue division: If modularity score improves
    • Stop division: If modularity score decreases or stays flat
    • Optimal level: Maximum modularity across all hierarchy levels

    Recursive Binary Splitting¶

    Algorithm Pseudocode:¶

    def recursive_modularity_clustering(graph):
    communities = []
    queue = [graph]

    while queue:
        current_graph = queue.pop(0)

        # Apply binary modularity clustering
        community_1, community_2, modularity_gain = binary_split(current_graph)

        if modularity_gain > threshold:
            queue.append(community_1)
            queue.append(community_2)
        else:
            communities.append(current_graph)

    return communities

    Advantages:¶

    1. Automatic stopping: No need to specify final number of communities
    2. Quality-driven: Divisions based on modularity improvement
    3. Hierarchical structure: Provides multiple levels of community organization
    4. Flexible granularity: Can stop at any level of the hierarchy

    Visual Example:¶

    Level 0: [All nodes] → Modularity = 0.0
Level 1: [Community A] [Community B] → Modularity = 0.4
Level 2: [Comm A1] [Comm A2] [Comm B1] [Comm B2] → Modularity = 0.6
Level 3: Further splits → Modularity = 0.55 (stop here)

    Optimal result: 4 communities at Level 2
